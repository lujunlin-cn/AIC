## 3. R83：真实实验比“5 折失败”更窄

[R83 原报告][r83-report]称“5 折源级留出”，但 [实现][r83-code]只将源 SHA256 哈希分为 5 桶，使用 `folds != args.folds - 1` 训练、最后一桶验证，没有轮流训练 5 次。因此准确称谓是 **五桶划分中的一次源级留出**，不能称作完整 5-fold cross-validation。

[归档 probe.json][r83-metrics]记录：5,886 片段、2,262 源；验证 1,128 片段、426 源；8 槽、7/8 保留率、仅两个合法窗口；26,786 参数；center F=0.02542356、BCE=0.02528073、policy=0.02542356、oracle=0.02887116。验证指标是片段平均，源包含多个片段时权重更高，不是 source macro。[指标实现][r83-code]。

三项限制影响失败解释：

1. **BCE 对照的 `pos_weight` 实际为正例数/负例数。** 若意图补偿稀疏正例，它与通常的负例数/正例数加权方向相反；不能将其视作已充分调平类别的历史强基线。源码也明确它只是本次小头，不是历史训练头。[实现][r83-code]、[probe 限制][r83-metrics]。
2. **等效用样本被硬标为第一个窗口。** `np.argmax(scores)` 对两个窗口平值返回 0；所有无正例片段都产生这种标签。`positive_rate=0.1108156` 是“至少有一个正例的验证片段比例”，不是正例帧占比；约 88.9% 验证片段没有正例，硬标签多数可以仅反映平值规则。实际所有平值的比例和训练标签分布未归档，不能补造。[实现][r83-code]、[归档指标][r83-metrics]。
3. **对齐与行为证据有限。** `load_rows` 按 `min(len(y), len(x), len(t))` 截短，再统一最少槽数，没有在此入口逐帧身份断言。报告声称策略完全退化到中心，但归档 JSON 只有均值，没有逐片段动作，单凭两个均值相等无法独立证明所有动作相同。[实现][r83-code]、[报告][r83-report]。

这些限制不是重启 interval 扫参的理由，也不能证明换正例权重就有效。它们只要求把结论限定为“这次 8 槽、两个窗口、当前监督构造的一次留出没有收益”，而不是“小模型、连续政策或完整视觉表示都无内容信号”。

## 4. R70 与 R84：相同观察，不同读出；统计口径需要统一

### 4.1 信息与监督路径

R70 的 `extract` 对一个关键帧图像运行一次冻结 V9 视觉塔，得到 token 网格；`feature_from_grid` 对 129 个最大合法窗口生成窗内均值 768d、窗外均值 768d、二者差 768d、位置 1d，即 `[129,2305]`。候选区域使用 floor/ceil token mask。其 `Head.make` 是 `2305→512→128` 后接两层四头候选自注意力。它没有把每个候选 crop 图像重新送入视觉塔。[R70 提取与 head][r70-code]。

R84 直接载入这些相同的 2305d 特征，使用 623,361 参数逐候选 MLP，优化 MSE + 0.30 KL + 0.50 坐标 SmoothL1。所谓坐标目标是 `softmax(native IoU / 0.08)` 对候选位置的期望；它没有新增人工坐标监督。推理仍取分数 argmax，softargmax 只是辅助损失。[R84 实现][r84-code]、[配置][r84-config]。R84 官方提取入口同样对整帧编码后池化候选。[官方入口][r84-infer]。

口径差异不足以改变结论：**R84 明显弱于 R70，不应把“打包成功”“改了算法”或“比中心好”当作主候选晋级。** R84 可作为已冻结附加对照；本轮公共空间 A 必须明确是 R70 topsoft。R84 报告的 checker、零 fallback、112,141 改框记录只证明已有工程输出，不证明官方效果。

另一个复现界限：当前 R70 主脚本的训练函数是 MSE；归档 README 描述了四种目标，但本轮已查入口没有 topsoft 的完整训练实现。[R70 主脚本][r70-code]、[目标变体报告][r70-objectives]。因此 A 使用身份核验后的冻结 topsoft checkpoint 及其 `mu/sd`；不能凭名称补造 topsoft 公式或声称已从头复现历史训练。新 B/C 则采用明确、完全归档的固定 MSE。

## 5. 现有监督是 T5 当前版本，不能套旧 B3/v1 分割

R70 数据由 T5_CROPHEAD_V3 表驱动。当前源码规定 RV train 为 001–080，dev 为 081–100；LIVE train/dev 来自 `live_train_index.jsonl`，以 `sha1(video_id) % 10 == 0` 留 dev。R70 归档实际统计为 **11,276 训练行、1,546 验证行；验证 RV 20 源、LIVE 148 源**。不要用旧 B3 的 RV 110 源、LIVE 1115/124/227 分割描述这批数据。[T5 划分与标签加载][t5-code]、[T5 预注册][t5-config]、[R70 实际统计][r70-metrics]、[旧 B3 版本][b3-config]。

原生监督路径是 RetargetVid 多标注者裁剪框与 LIVE 的 `raw_ltrb`/原生标注 frame；R70 `table_gt` 只在关键帧确实存在于 `gf` 时计算 129 候选对人工框的平均 IoU。T5 的 `J` 历史上经过 Qwen 点可用性筛选；R70 复用的是这批帧和 native GT，不是把 Qwen 点当标签。因此应披露采样的历史筛选偏差，同时避免把训练监督描述成教师 crop。[T5 `load_unit`][t5-code]、[R70 `table_gt`][r70-code]。

这里的“native”说明标签来源与原生坐标，不保证历史评测脚本的面积定义完全相同：R70 `iou` 使用连续边界面积；更早 RV benchmark 曾用取整和 inclusive `+1`。新 A/B/C 必须共享 R70 的候选与连续 IoU 主口径，任何 benchmark 复核另列，不能混合比较。[R70 IoU][r70-code]、[历史面积差异审计][spatial-review]。

**所有已展示结果的池都按已暴露集合管理。** 当前 dev 已用于 R70 四目标选择和 R84；RV confirm2（601–700）早已用于 T1/T2 等决策，LIVE val/confirm3 也已在 T5 及后续报告出现。旧文件曾写“never used”只对当时成立，不能在 2026-10-19 再称新盲确认。它们可作公开外部诊断，不能包装成未见确认集。[T5 原预注册][t5-config]、[实验记录 T5/confirm2/LIVE val][experiments]。如果找不到带访问日志的真正未暴露池，就诚实报告一次固定协议的开发证据，不通过改名制造独立性。

### 5.1 重新编码前的关键数据合同

R70 shard 保存 `x/y/source/name/ratio/W/H/offsets`，**不保存 frame ID 或图像 SHA**。因此新 crop 不能按旧 shard 行号猜配图片；必须由原 T5 单元的 `keys[J]` 重建明确的 `(dataset, source, frame, ratio, candidate)` 绑定。[R70 `flush_rows` 与 `extract`][r70-code]。

新 manifest 应记录原生 W/H、PNG 实际尺寸、从标签坐标到 PNG 像素的显式变换、原帧/PTS（可得时）、image SHA、annotation/table SHA、split、candidate box、processor 与视觉权重 SHA。PNG 如经缩放，必须使用该变换裁剪；不能以“坐标看起来小于某阈值”猜测比例。三个臂必须同样本、同候选、同标签，训练归一化只用 train；加载时显式允许 train/dev 名称，并断言源不交叉。R84 的 `te=~tr` 会把任何非 train shard 当验证，不能原样拿它来保护另存的确认集。[R84 loader][r84-code]。

## 6. 实际 crop 编码不是全项目首次出现

已有 `qwen_crop_rerank.py` 的 V4 E4 让 **Qwen3-VL-32B** 同看整帧与实际候选 crop，正反两种顺序一致才接受；这是大模型生成式候选选择，按当前规则不能原样作为 ≤9B 推理模块。[旧 crop rerank][old-crops]。

R8 也生成过 128 张真实 crop，用于 Qwen 3B/7B 的 NPU parity 与吞吐诊断；其正式 SFT 入口则是单张整图加候选坐标文本，并不等于共享 V9、native IoU 监督的多 crop 判别实验。[R8 crop 生成][r8-crops]、[parity][r8-parity]、[SFT][r8-sft]。旧 `r8_make_crops.py` 含启发式坐标缩放判断，不应复用为 R85 几何合同。

准确的新颖性限定是：**相对 R70/R84 的单全图网格路径，新增共享冻结 V9 的真实候选 crop 观察，并用容量和布局匹配的干预判断信息增量。** 不能写成“项目之前从未看过真实 crop”。

## 7. R85：采用的最小三臂设计

以下是本轮接受的方案；还不是已完成实验。

| 臂 | 每候选输入 | 训练/身份 | 作用 |
|---|---|---|---|
| A：R70 topsoft | 原 2305d | 冻结已归档 topsoft checkpoint、原 norm，核验真实身份 | 已评分空间实用基线；不是与 B/C loss 匹配的因果对照 |
| B：旧网格布局 | 原 2305d + 原全图 grid 上该候选 ROI 的 2×2 面积加权池化 3072d | `Head(d=5377)`、固定 MSE、固定 seed/steps/批次 | 控制参数容量与旧观察中的局部布局信息 |
| C：真实 crop | 原 2305d + 同一冻结 V9 塔编码实际候选 crop 后的 2×2 面积加权池化 3072d | 与 B 完全相同的 head、MSE、初始化与训练日程 | 检验重新编码的额外观察/表示作用 |

候选保持 129 个最大合法比例窗；不同时增加尺度、移动候选集合、改监督、扫描融合、增加门控或平滑。原 2305d 与附加分支都使用同一版本视觉权重和明确几何。B/C 共享完全相同的初始 state_dict 和预先生成的样本批次序列，比仅声称“同 seed”更可靠。各臂按自己的训练特征计算 norm，禁止验证样本进入标准化。

最初提出的 B“重复四次旧 win768”已撤下：重复列经首层线性映射可折叠成同一均值的线性映射，只匹配名义参数数目，没有匹配 C 的 2×2 布局与有效输入维度。若只用那个弱对照，C 的优势可能完全来自读出原网格已含的布局信息。新 B 正是为了否定这一竞争解释。

**C−B 是核心机制比较，C−A 是候选晋级门，二者缺一不可。** 由于 A 是 topsoft、B/C 是明确 MSE，C−A 的差异包含输入、容量和训练目标；不能把它单独称作观察信息的因果效应。官方 R85 对 R70 固定了时间与分母、只替换空间子系统；“只改空间子系统”也不等于“空间内部只改了一个数学算子”。

一个无需另训模型的辅助诊断是在验证阶段，按固定随机种子打乱同一帧候选之间的附加 crop 特征配对，保持原 2305d、候选位置和标签不变。若 C 优势消失，说明模型依赖候选与 crop 的对应关系；但此干预有分布外效应，只能辅助解释，不能替代训练匹配的 B。候选整体换序时，要同时移动全部特征及坐标、再逆置输出，用于验证读出没有错误使用数组索引。

## 8. 指标、竞争解释与预先停止条件

主指标统一为源级平均的 annotator-mean candidate IoU；固定源内先聚合，再报告 RV/LIVE 各域、两域等权均值与合并 source macro。报告 candidate oracle regret、train/dev 差距和逐源配对差值；置信区间按源重采样、在两域内分层，不能把 1,546 行视作独立样本。[现有多源标签与指标实现][r70-code]、[R70 原始分域结果][r70-metrics]。

| 结果 | 可接受解释 | 下一步 |
|---|---|---|
| B>A，C≈B | 原网格布局读出足以解释改进；真实 crop 的边际价值未获支持 | 关闭本次重编码主张；不拿 C 的参数或吞吐代价换名包装 |
| C>B，但 C≤A | 新观察对当前 MSE 头有作用，但尚未胜过现役空间读出 | 不出晋级包，不因 C>B 忽略 A |
| C 仅 train 增益，dev 无收益 | 容量/拟合或跨源迁移限制 | 不通过扩大模型、换 seed、看结果后调池来救此实验 |
| C>A 且 C>B，两个域均同向 | 对额外局部观察有机制证据，且有公共实用增益 | 才进入一次固定候选的全流程验证；仍不预测官方涨分 |
| 关键优势仅在错误坐标/错帧配对样本出现 | 数据合同或实现混杂 | 修正绑定并将此前运行标成无效；不能保留污染指标 |

已冻结晋级门见 `configs/R85_REAL_CROP_OBSERVATION.json`：每个预定 seed、每个 DEV 域分别要求 C−A 和 C−B 的源级平均 IoU 至少 +0.01，源级配对 95% 区间下界 >0，且至少 2/3 源严格改善；任一不满足即不宣布通过。同时单列候选配对破坏诊断：C 在每个域、每个 seed 的置换后均值必须下降，否则停止“对应候选内容产生收益”的解释。这是资源分配与机制证据门，不是官方分代理。若区间跨零，结论是这次固定协议证据不足，不是数学证明新观察不存在。已暴露 dev 上通过这些门也不能被称为独立确认或官方效果承诺。

缺少某种 native 方向/比例的监督时，要报告覆盖空缺；旋转现有图像或交换坐标可以测试数值等变性，不能冒充新增自然竖屏裁剪标签。[历史空间覆盖限制][spatial-review]。这种空缺属于迁移风险，而不是用官方视频人工标注来补洞的理由。

## 9. 参数组成、运行成本与证明边界

R84 报告给出的实际组成是 TimeLens2 `8,767,123,696` + V9 tower `85,843,200` + R84 head `623,361` = **8,853,590,257**，无 YuNet。R70 manifest 给出总量 **8,854,531,425**，空间部分 `87,407,729` 包含 V9、1,511,425 参数 R70 head 和 YuNet；由这些数相减，YuNet 对应 53,104 参数。[R84 组成][r84-config]、[R70 元数据][r70-manifest]、[R70 head][r70-code]。本审阅没有在 GPU 上重新实例化并核对这些历史组件，不能把报告数字当成本轮实载证明。

若 R85 仅保留 TimeLens2、同一 V9 tower 和 `Head(d=5377)`，其**结构预期**如下：

| 组件 | 预期参数 |
|---|---:|
| TimeLens2 | 8,767,123,696 |
| 同一 V9 vision tower，整帧/crop 共享 | 85,843,200 |
| R85 head：1,511,425 + 3072×512 | 3,084,289 |
| 总计 | **8,856,051,185 = 8.856051185B** |
| 距 9B 余量 | 143,948,815 |

这项预算最初由现有 head 的第一层输入扩维推导；本轮随后的 CPU 工程回归已实际实例化并核实 head 为 3,084,289 参数，**全套预训练权重仍未加载验证**。最终必须从真实 loader 与权重张量清单验证：是否增加 projector、仍调用 R70/B3/YuNet fallback、是否错误加载完整语言模型。任何生成最终预测所需的模型，包括生成复用时间分数的 TimeLens2，都要计入；缓存不是免计理由。[现行参数规则][rules]。

同一组冻结 V9 权重用于 129 次前向，只计一份参数；若复制成独立模型、额外适配或保留多个不同头，则按实际系统核实，不以“共享”名称代替权重身份。训练对照 A/B 的头不参与 C 最终推理时，不应加进 C 的推理参数；反过来，部署调用了就不能漏计。

计算成本与参数成本不同。按当前行数直接计算，完整公共 train/dev 的 129 crop 分支约 **1,654,038 次候选图像编码**；若官方沿用报告中的 8,848 关键帧，则约 **1,141,392 次**，另加全图编码。只保存公共 FP16 的 `[129,3072]` 新特征就约 **10.16 GB**，不含原特征、索引和临时批次。这些是未去重的数量算术，不是墙钟或显存实测。[公共行数][r70-metrics]、[官方关键帧数][r84-config]。

因此先对合法公共图像做有明确数量的吞吐、批处理与保存重载检查，记录实际 GPU/软件环境，再决定全量提取；不得沿用历史硬件性能作为当前保证。可按同图同几何 SHA 去重相同 crop，但映射必须完整可逆，不能为省成本在结果出来后改成另一套候选数量。

## 10. 官方上传前仍须满足的边界

1. **身份和输入**：A checkpoint/norm、V9 processor/weights、公开数据 manifest、训练/验证 split 和全部 crop 配对都可追溯；恢复不到 A 的真实资产就不能将替代头命名为 R70。旧 V9/B3 权重身份问题不会因 R70 可用而自动消失。[R70 的非 B3 声明][r70-code]、[历史 B3 身份审计][b3-path]。
2. **模型证据**：B/C 完成真实冻结视觉特征实验和独立源级汇总，满足预注册门；不得用 synthetic 测试通过替代真实训练结果。新包必须明确 R54 原帧集合逐视频完全相同，仅替换合法空间框。
3. **参数与包**：真实组件总参数 ≤9B；当前合同 checker、独立 checker、ZIP 解压往返一致；记录 predictions/ZIP/模型/配置 SHA，以及覆盖、重复帧、ratio、边界、NaN、回退情况。checker 只能证明合同，不能证明新模型优于 R70。
4. **决策**：R84 未评分且公共结果较弱，不作成功锚；R71 保留最高分回退。本轮不自动上传；如果新 C 未满足证据门、运行资产不足或合同失败，保留可复现负结果，明确没有形成晋级包。不能为了交付一个 ZIP 而把未运行或较差模型包装成突破候选。

一项具体历史资产问题：当前 [R70 manifest][r70-manifest] 在 JSON 对象后含字面量 `\\n`，标准 `json.loads` 会报 `Extra data`。本审阅只用 `JSONDecoder.raw_decode` 读取对象并确认该后缀，未修改历史文件或 ZIP。这不证明历史 predictions 或官方上传包无效；新报告和新包应使用标准 JSON 写出，不能通过宽松解析掩盖新产物的问题。

## 11. 推荐执行顺序

先恢复并核验 R70 A、T5 表和源图像身份；从原图同时提取 B/C 需要的特征并保存显式 frame/candidate manifest；用一个预先冻结的训练日程运行 B/C，完成源级配对结果与几何/配对干预；通过 C−A、C−B 两道门后，才按 R54 精确时间掩码推理并导出唯一 R85 候选。该路径把新增计算集中在“真实 crop 观察是否值得”这一条可否证问题上，保留负结果，并且没有读取或重建官方 GT 的环节。
