## 一、任务定义（实测，非推测）

- **数据集**：426 个 YouTube 短视频（"gif 高光"任务，来自 PHD² 域）。时长中位 **14.1 秒**（p10=7s, p90=36s），总帧数 median≈550 帧/视频。66% 横屏 16:9 / 29% 竖屏 9:16。
- **每帧要输出**：该帧上"最值得保留的裁剪窗口"（[x, y, width]，比例固定为 16:9 或 9:16；滑窗沿长边自由滑动，短边贴齐）。
- **官方评分**（我方复刻的算术，与平台一致）：

```
对每个视频:
    iou_sum   = Σ_{预测帧 f 且 f ∈ GT帧} IoU(预测框_f, GT框_f)   # 只有帧号同时出现在预测和GT才累加
    F1_video  = 2 · iou_sum / (N_pred + N_gt)
Score = 100 · mean_videos(F1_video) · k_size
```

`k_size` 是模型大小阶梯系数（≤100MB→1.00，100–500MB→0.95，500MB–9GB→0.90）。

**关键结构性事实**：
1. GT 只标注"高光帧"，**不是**每一帧都有 GT。在 PHD² 训练域实测正例率 **p ≈ 0.39**（高光帧占全部帧的 39%）。
2. `N_pred` 是**我们提交的预测帧数**。预测所有帧 → N_pred≈550/视频，**分母被撑到最大**。
3. 预测一帧只有在**帧号命中 GT** 时才贡献分子；保留一帧不在 GT 的帧**只增加分母、不增加分子**。
4. 计分是 **macro（逐视频 F1 再平均）**，不是 micro。

**用这个公式做数值分解**（p=0.39, 命中帧 IoU=m=0.62）：

| 策略 | F1 | 平台分 |
|---|---|---|
| 预测全部帧（keep=1.0） | 2·m·p/(1+p) = **0.34** | 34 |
| 完美排序 + keep=p（只留真正的高光帧）| m = **0.62** | 62 |
| keep=0.80（当前最优固定档）| ≈0.36–0.40 | 36–40 |

**即：F1 的理论上限是"命中帧的框 IoU"本身（约 0.62），当前 0.34，理论剩余空间约 0.28 F1 ≈ 28 分，全部来自"更准确地决定保留哪些帧"（时间排序精度）。**

## 三、我们已排除的三条路（别浪费时间）

1. **换更大的骨干/更好的特征**：当前视觉塔是 Siglip2 NaFlex（LFM2.5-VL-450M 内嵌），冻结特征在本地池上已有判别力，瓶颈不是特征质量而是**怎么用这些特征做帧排序**。
2. **k_size 系数套利**：平台按模型文件物理大小核验，剥离未调用的语言模型（推理时确实从未加载）不改变系数。已验证 34.73 vs 34.75。
3. **跨域蒸馏/辅助域**：QVHighlights（7,218 视频，22 标注者密集 saliency）训练的时间头在**其自身域** val AP=0.809（很强），但跨到目标域 AP 掉到 0.531（原生头 0.695），keep 掩码模拟里所有保留率的置信区间都跨零，与原生头融合反而更差。**域内强 ≠ 跨域可用**，这条已被实证证伪。

## 四、我们已经定量测出的三个事实（请以此为基础）

1. **keep 率不是瓶颈**：全量扫描（3,958 片段/1,987 源）显示 F1 峰值在 **keep=0.70–0.80**（F1=0.356 vs 全帧 0.326），已提交包用的正是 0.80。更激进的保留率反而因丢召回而变差。

2. **原生时间头 vs 同预算随机**：keep=0.5 时 F1=0.3385，随机同预算=0.2516，**只高 0.087**。模型排序能力很弱。

3. **一次"看起来成功"实为泄漏的实验**：我们实现了 F1 最优化的经典不动点规则（逐视频自适应保留帧数，而不是固定比例），初测 F1=0.4727 vs 固定 0.3977，看起来是 +0.075 的突破。**复查发现代码里用了真实 GT 的正例数来估计每个视频该留多少帧——信息泄漏**。改成只用打分器自身输出后，F1=0.3696，反而比固定率差 0.028。

**这次失败告诉我们一个我们之前没意识到的事**：F1 最优的自适应保留规则，**前提是打分器能无偏估计"这个视频有多少高光帧"**，也就是**概率校准**。我们现有的头只做了排序训练（MSE 回归），输出经 sigmoid 后既不校准、也不跨视频可比。所以任何依赖绝对概率的决策（自适应阈值、期望 F1 优化、跨视频预算分配）目前都无法工作。

## 五、请你重点研究的六个方向

### 方向 1：概率校准是不是被忽视的关键环节？
既然自适应决策规则的失败根因是"无法估计每视频正例数"，请研究：
- 在"macro F1 + 帧级二值标签"这个具体目标下，什么样的训练目标能同时得到**好的排序**和**可用的校准**？（例如：带不确定性/拉普拉斯采样的回归、Platt/保序校准后处理、以 F1 为直接目标的 ranking loss、可学习的 uncertainty head）
- 校准后的概率如何最优地转化为"保留哪些帧"？请给出**在不知道真实 N_gt 时**的可行决策规则，并对它的理论性质（是否收敛到 F1 最优）做分析。
- 期望 F1 最大化（Expected Maximization of F-measure, E-maxF）在这个场景是否适用？它的理论保证是什么？需要什么校准质量？

### 方向 2：逐视频 macro F1 的结构是否被充分利用？
- 计分是逐视频 F1 再平均。对单个视频，F1 的最优保留策略取决于该视频正例率 p_v。请分析：给定打分器质量（用 AUC/AP 刻画），macro 平均下的最优策略是什么？是不是应该让某些视频几乎全删、某些全留？
- 请**给出理论或可计算的界**：在打分器 AUC=A 的约束下，macro F1 的上界是多少？如果 A=0.75，当前 0.34，最多能到多少？**这个上界会告诉我们"继续提升 AUC 是否值得投入"。**

### 方向 3：框 IoU 那一侧是否也有空间？
我们一直假设"命中帧的框 IoU ~0.62 是天花板"，但没验证过。请分析：在这个任务里，空间定位精度和帧排序精度的**边际收益如何权衡**？（框 IoU 从 0.62 提到 0.75 值多少分？帧排序 AP 从当前提到 0.9 值多少分？）哪一个是更值得投的方向？

### 方向 4：数据与标签形态
- 我们的高光片段（8-14 秒、1 秒网格、正例率 0.39）来自 PHD² GIF 区间标注。已知 PHD² 的 GIF 区间来自"用户把视频转成 GIF"的行为，**这本质上是"人类觉得值得做 GIF 的片段"**，它和比赛评测的"精彩帧"判据是否同源？如果不完全同源，标注噪声有多大？
- 请研究：**如何用弱监督/行为信号替代或增强这种噪声标签**（例如从真实 GIF 文件的帧间差异反推高光、用观看行为、用美学模型）。

### 方向 5：模型结构与特征用法
- 当前做法：冻结 Siglip2 视觉塔 → 每帧 mean-pooling 成 768 维 → 一个 3 块膨胀 TCN（感受野 15 帧、约 20 万参数）逐帧打分。请分析这个架构的信息瓶颈在哪。
- 有没有更好的时序建模方式（考虑到视频只有 8-15 秒、且要求逐帧输出）？
- mean-pooling 把整帧压成一个向量。如果改成保留 token 序列、或用 attention pooling、或加入相邻帧差分/optical flow，对"判断这一帧是否精彩"是否有实质帮助？为什么？

### 方向 6：赛制层面的非对称机会
- `k_size` 是阶梯函数：≤100MB→1.00，100–500MB→0.95，500MB–9GB→0.90，>9GB 超限。**从 0.90 跨到 0.95 等于凭空 +5.56%。**
- 我们试过"只声明推理时真正加载的权重"，平台不认（34.73 vs 34.75）。请分析：有没有**合规且平台会认**的方式减小模型体积（比如极端量化到 ≤100MB 直接吃 1.00 档）？对精度损失多少，对分数净收益多少？
- 请给出"模型压缩 vs 提升 raw 分"在阶梯约束下的**最优投入配比**。
