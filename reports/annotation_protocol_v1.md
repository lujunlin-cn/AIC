# AIC 人工先验标注标准 v1.2

日期：2026-10-17（v1.2：取消逐帧盲标确认，非高光允许跳过信息依赖）

批次：`AIC_MANUAL_ANNOTATION_V1`

适用界面：`configs/label_studio_annotation_v1.xml`

## 0. 这轮标什么

标注对象是一个 30 秒视频窗口中的 1 fps 采样帧。问题是：

> 如果只能从这个窗口选少量帧制作短片，这一帧是否值得被选中？

这里的“高光”是对通用视频短片的保留价值，包含动作、结果、关键互动、重要信息和明显反应。它不是 QVHighlights 的 query 相关性，也不是“画面好看”、检测框紧不紧或主体是否居中的评分。

这 12 个视频只用于机制诊断，不能当作 AIC 官方 GT。首轮不显示 QVH query、类别、抽样原因、模型分数或其他人的标注。

QVHighlights 的 query 是该数据集原来的搜索描述，例如“有人完成某动作”；它会诱导标注者只找这件事，所以首轮不展示。旧界面的“未看查询”只是盲标流程确认，不是高光标签，也不是要求你去寻找查询。v1.2已隐藏该选项并取消必填，保留旧导出字段以兼容已有结果。不自动填写“未看查询”来替标注者作事实确认；盲标展示政策记在项目协议里。

## 1. 标注前的固定流程

每个视频按以下顺序完成，不跳步：

1. **先完整播放 30 秒 MP4，必须打开声音。** 可以暂停、回放和调节音量，但不能先看逐帧图片再猜整段事件。
   Label Studio任务上方已有播放器；同一`video_id`完整看一次后再标该视频的30张图，换视频后重新观看。标题的`exported time`与播放器秒数一致。本批次是30秒窗口，不是原始长视频全片；窗口之外的事件不能猜测。
2. **先在脑中建立事件时间线，不立即逐帧打分。** 记住动作开始、变化、完成、结果和反应的大致位置。
3. **按 1 fps 图片顺序逐帧标注。** 每帧填写 `generic_highlight`、`event_phase`、`event_type` 和 `confidence`；等级0/1的 `needs_context` 可以留空，等级2/3请填写，不确定时可选“无法判断”并说明缺少的证据。
4. **只对等级 2 或 3 的帧考虑构图框。** 先判断是否真的值得保留，再决定是否存在合理窗口。
5. 标注者不得查看另一人的结果。重叠视频必须在双方都导出后才进行比较或讨论。

如果音频无法播放，不能假定“没有声音”。在备注写 `audio_unavailable`；若缺失音频影响高光判断，`needs_context` 选“无法判断”、整体置信度选“低”，并保留该帧供质量审计。等级0/1的信息依赖仍可留空，不因为缺字段阻止提交。

## 2. `generic_highlight`：四级保留价值

等级按**同一视频内部的相对保留价值**判断，不要求不同视频的 2 分具有相同绝对强度。先问“是否有可指出的事件、信息或状态变化”，再问“在有限预算下是否值得占一个帧位”。

| 值 | 标准 | 典型例子 |
|---|---|---|
| `0普通` | 明确没有值得保留的事件或信息；背景、等待、重复、普通状态、无关画面。 | 静止等待、重复走路、无变化的房间或景色。 |
| `1有信息` | 能帮助理解人物、场景或事件，但单独放进短片的价值低；通常是铺垫、过渡或一般状态。 | 动作前准备、讲话中没有关键内容的一帧、结果前的普通姿态。 |
| `2值得保留` | 有明确动作、关系、状态变化、结果或信息；若预算允许，会保留，但不是整段最决定性的一帧。 | 动作进行中的清晰阶段、能看懂互动的一帧、结果出现前后有解释力的画面。 |
| `3高光核心` | 该窗口中最应该保留的少数决定性时刻；删掉会明显损失事件、结果或情绪信息。 | 动作完成、结果揭示、关键互动、最强反应、最重要的屏幕信息。 |
| `不确定` | 由于遮挡、模糊、过曝、语义不清、事件跨出窗口或音频/语言不可得，无法可靠区分 0–3。 | 只看到动作的一角，无法判断发生了什么；关键信息只在听不清的语音中。 |

### 2.1 0、1、2、3 的裁决顺序

对每帧按下面的判断树走：

```text
能否指出具体事件、信息或状态变化？
├─ 不能，但证据充分表明只是普通/重复/等待 → 0
├─ 不能，且证据不足或关键内容不可见 → 不确定
└─ 能
   ├─ 只有理解背景的作用，有限预算不会单独保留 → 1
   ├─ 有独立保留价值，但还有更决定性的帧 → 2
   └─ 是结果、峰值或不可替代的核心时刻 → 3
```

不要因为以下因素单独给 2 或 3：画面清晰、主体居中、色彩鲜艳、镜头运动大、开头/结尾位置、构图漂亮或与未知的 QVH query 可能相关。

同一动作持续多帧时，不要把所有帧都标为 3。通常把最能说明结果或状态的帧标 3，其他仍有解释力的阶段标 2，纯重复帧标 1 或 0。相邻帧难以区分时，优先给主体更完整、遮挡更少、结果更清楚的一帧更高等级。

`不确定` 不是“我觉得不精彩”，而是“现有证据不足以判断”。不能为了让分布好看而把不确定改成 0。

允许一个窗口完全没有等级2/3，不强制选出高光。0与1仍按是否具有背景/铺垫信息区分；没有高光不等于没有事件，普通走路等仍可属于“动作”“进行中”。

## 3. `event_phase`：事件处于哪一阶段

- `铺垫`：关键动作或结果尚未发生，主要提供人物、场景、目标或背景。
- `进行中`：动作、互动或信息正在展开，当前帧本身显示过程的一部分。
- `完成或结果`：动作完成、结果出现或关键状态被揭示。
- `结果后反应`：结果已发生，当前价值主要来自人物、观众或环境反应。
- `无事件或无法判断`：没有可识别事件，或证据不足以判断阶段。

按“当前帧为什么值得保留”选择阶段。结果画面同时含有人物表情时：若价值主要是结果本身，选“完成或结果”；若结果已经清楚、价值主要是情绪反应，选“结果后反应”。

## 4. `needs_context`：当前帧能否独立解释价值

先判断高光等级，再填本项。等级0/1可直接跳过；等级2/3请按下表的含义填写。这里问“判断价值所需的证据”，不是“标注者有没有播放视频”：即使你按流程看完了视频，当前帧本身就能表达价值时仍选“当前帧足够”。界面设置为可选，避免对非高光强加不适用的诊断；质检时单独报告等级2/3的漏填，绝不把漏填当成“当前帧足够”。

- `当前帧足够`：只看这张图就能理解主体、事件或信息为什么值得保留。
- `需要前后过程`：必须知道动作之前、之后或状态变化，静态帧本身不足；例如“正在接近目标”只有看完成结果才有意义。
- `需要声音或语言`：关键价值来自说话内容、语气、掌声、叫喊、音乐或其他音频，静态图无法替代。
- `无法判断`：即使看过完整窗口仍无法确定价值来源。

例如，明显的结果画面可选“当前帧足够”；要对照起跳和落地才知道动作是否成功，选“需要前后过程”；笑点或关键结论只在说话内容里，选“需要声音或语言”。字幕已在当前图片中清楚表达关键信息时，可以选“当前帧足够”。

若同时需要前后过程和声音/语言，选择“需要声音或语言”，并在备注写“同时需要前后过程”。这个字段描述**信息依赖**，不降低高光等级：一个必须结合上下文才能理解的结果仍可以是 3。

## 5. `event_type` 和 `confidence`

`event_type` 只选最主要的一类：动作、结果或揭示、情绪或反应、人物互动、信息或字幕、视觉奇观或场景、其他、无事件。若有第二类很重要，在备注补充，不改变单选主类。

`confidence` 是对本帧整体判断的置信度：

- `高`：事件和保留等级都清楚；
- `中`：大致判断稳定，但阶段、价值或信息来源有轻微歧义；
- `低`：遮挡、模糊、语义或音频造成明显不确定。若 `generic_highlight=不确定`，必须选低。

## 6. 构图框：什么时候画、画什么

### 6.1 本批次框的语义边界

本批次任务没有逐视频 `targetRatioWH`，因此 `crop_box` 是**自由比例的构图可行性诊断框**，不是官方 native crop GT，也不能直接转换成提交的 `[x,y,w]`。它回答的是：高光帧是否存在一个稳定、可解释的保留窗口。

未来若要训练或评价空间模型，必须另建带 `targetRatioWH` 的标注批次，并按该比例画合法窗口；不能把本批次自由比例框当作那种监督。

### 6.2 画框条件

只有 `generic_highlight=2` 或 `3` 才画框。框表示“愿意保留的一个画面窗口”，不是紧致检测框：

- 优先包含高光相关主体和动作关系；
- 必要时同时包含结果、字幕、屏幕信息或完整景别；
- 多人互动画一个能保留关系的整体窗口，不给每个人分别画框；
- 有多个同样合理的窗口时，选择最能解释高光价值的一个，并在备注写另一种合理选择；
- 没有稳定合理窗口时不画框，`composition_confidence` 选“低或无合理框”；
- 不为了让每个高光帧都有框而强行框主体。

`crop_reason` 选择画框的原因，可多选：主体完整、动作关系、结果信息、字幕保留、整体构图。`composition_confidence` 表示该窗口的稳定性，不表示检测框精度。

## 7. 双人标注和争议处理

6 个重叠视频由两人独立完成。双方导出前不得交换具体帧、等级、框或备注。导出后：

1. 保留两份原始结果，不覆盖、不先做“裁判改写”；
2. 按视频分别统计等级分布、加权等级一致性、阶段一致性、上下文/声音依赖一致性和框的重叠情况；不要只把所有帧混在一起算一个比例；
3. 分歧本身是语义不确定性的证据，不自动视为某一人错误；
4. 若后续小实验必须生成一个软目标，保留两人的等级分布或均值，并同时保留分歧/低置信度掩码；不得把两个人的框坐标简单平均成唯一真值。

单人视频只能用于描述性诊断，不能报告标注者一致性。

## 8. 标注完成后的最小质检

- 每帧都有高光等级、事件阶段、事件类型和置信度四个核心字段；等级0/1的信息依赖留空按“不适用”处理，不计入信息依赖比例。等级2/3的漏填按缺失值单独报告，不自动补标签；`generic_highlight=2/3` 才检查构图框。旧结果的`query_relevance`保留，但不要求新结果出现它。
- 一个 30 秒窗口通常只有少量 3；若几乎每帧都是 2/3，重新比较相邻帧的相对价值。
- 检查是否把清晰度、居中、运动、开头/结尾或 query 相关性当成高光理由。
- 检查所有“需要声音或语言”的帧是否真的在完整视频中听到相应证据。
- 导出后保留 `video_id`、`source_time_sec`、选择字段、框坐标和备注。JPEG/MP4 时间必须通过 manifest 回映射到源视频，不能直接当作 AIC 原始 frame 编号。

## 9. 这轮结果如何使用

先报告四项机制量：

1. 人工高光与 QVH query 区间的错位；
2. 高光核心中依赖前后过程或声音/语言的比例；
3. 高光等级与“有稳定构图窗口”的关系；
4. 双人分歧集中在哪些事件类型和阶段。

只有在这些量能区分路线后，才决定是否改变时间观测、加入音频/事件结构、做联合时间-空间效用，或重新设计监督。不能用这 12 个视频直接声称官方分数提升。
