# 路线 10：Video-ORA 冻结大模型与分几何推理管线

整理日期：2026-11-07。总入口：[index.md](index.md)。最新状态以2026-11-06仓库核对、最终P2产物及后续明确回分为准，覆盖较早“仍在训练／等待回分”的条目。

## 主路线及为什么与前期不同

早中期通常让小时间头选帧、小空间头选窗口；本路线使用冻结 `OraRL/Video-ORA-9B` 进行时间事件与主体理解，再按几何路由启用两份小空间LoRA。基座本身已接近9B，因此添加任何新模块都必须算完整参数。

实际合同为：`原视频 → 真实PTS FrameBank → 30秒窗口/5秒重叠/最多64帧/640尺度 → 原生segments → 原始帧展开 → 主体锚点 → 几何A或B → 平滑与QP投影 → [x,y,w]`。

时间和主体阶段关闭空间LoRA；空间阶段按分支启用。A处理横向画面转9:16的自由x轴，B处理需要上下裁剪到16:9的几何。A/B是本家族空间adapter，不是早期CNN/ViT路线。

## 产物身份与可复现边界

42.49固定包ZIP SHA256为`7da198e794f0e6029f92413f56b9e22bf01c97c83c840caaec30db4b909191ea`。其输出133921帧，不能与42.48原始历史摘要134776帧混称“逐字节复现”。差别需要由输入、舍入、解码/采样合同解释，而不能从ZIP大小推断精度。

最终P2=42.74是同一家族后续空间配置；有426原运行和几何验证，但整理后的便携作品目录没有在本轮重新执行完整426。2026-11-07回顾也没有重新训练、登录官方评分或运行GPU评测。

原计划中的GPU地址、硬件型号与时限都是当时记录。项目用过V100、910A、RTX4080/4090、PRO6000等，未来资源须实时探查，不能从某个历史配置直接启动。

## 当前判断与讨论题

这是目前复赛已记录最好系统的基础。42.49→42.74的末期增量来自空间训练与后处理，不来自已验证成功的时间RL。如何保留其部署合同，是所有后训练比较的必要条件。

1. 为什么原生冻结时间模型明显超过旧时间头：更好的事件表示、观察合同、区间政策还是空间链？怎样做能识别这些原因的对照？
2. 参数余量只有约22.85万保守元素时，应训练替换现有adapter、合并单分支，还是重新分配模型容量？
3. 哪些已验证合同可迁移到更小模型：真实PTS、窗口重叠、原生区间、主体锚点还是分几何适配？
