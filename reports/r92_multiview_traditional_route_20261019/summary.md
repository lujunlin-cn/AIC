# R92 传统处理多视图路线复核（2026-10-19）

## 资料与结论范围

本报告复核仓库根目录的 `传统处理接入方案.pdf`。文件 SHA256 为
`04482190c7ba9d90b527175648abfdddaccc9687b26d9309d98f45055635a7ef`，12 页，
由 PDF 文本层提取出 25,153 字节。PDF 是研究讨论稿，不是经过本项目复现实验的外部证据；
其中论文结果只用于提出机制假设，不能直接换算成 AIC 官方分数。

核心判断：**方案值得继续，但必须把“传统特征拼接”改成“保留空间形状的多视图、目标域时间监督、固定预算和固定空间输出的判别实验”。**

## PDF 真正提出了什么

讨论稿中的有效部分有四点：

1. RGB、低频结构、高频结构、运动补偿残差和构图候选应作为不同视图输入，让网络学习视图之间的联合关系；不能把每个视图先压成一个亮度、边缘密度或运动幅度标量。
2. 运动视图应尽量去除全局相机运动。原始帧差把相机摇动、切镜和主体运动混在一起，不能直接当“动作显著性”。
3. 时间模型应看到邻近帧和事件上下文，输出与原始 frame ID 对齐的帧效用；运动峰值不一定是标注者选择的高光时刻。
4. 构图 ROI 视图可以用于帧效用，但它只能在目标域证据支持时接入时间排序，不能因为候选框的公开 IoU 变好就假设时间价值也变好。

“滤波创造新信息”不是该路线的理论依据。对确定性变换 `T(X)`，有
`I(Y;T(X)) <= I(Y;X)`；潜在收益来自有限模型的归纳偏置、优化条件和对局部结构的显式保留。

## 与现有证据的精确关系

| 既有实验 | 实际做法 | 能否关闭 PDF 路线 |
|---|---|---|
| R89 | 灰度梯度、局部对比、差分、清晰度、窗口几何的标量/候选统计，ridge 读出空间 IoU | 不能。它支持低层结构对空间读出有小增量，但没有学习多视图图像表征 |
| R90 | 32D 低层 bank、差分/短均值、语义 novelty/速度/加速度的标量拼接，TVSum 源级代理 | 不能。它关闭的是“简单低维 bank 直接替代语义或拼接就有效”，不是空间图上的多视图时序编码 |
| R91 | 冻结 ResNet18 + TVSum 线性读出，约 98.6M 参数 | 不能。它是小模型和监督迁移对照，尚无官方回分 |
| R70/R82 | 空间 utility 用于时间重排；R82 官方 36.20 低于 R54=36.22 | 强烈提醒 ROI/utility 不可直接当高光标签，但不否定它作为条件视图 |

因此，PDF 建议的“RGB + 图像视图 + 时序网络”在本项目中仍是未封闭分支；但它必须与 R90 的标量 bank 彻底区分，不能把重复跑标量特征称为新实验。

## 我接受和修正的部分

### 接受

- **低频结构**可能帮助小模型判断主体布局、画面重心和大尺度构图。
- **高频结构**可能帮助识别局部清晰度、边界和主体完整性，但也容易学到压缩噪声和纹理捷径。
- **运动补偿残差**比未配准的相邻差分更接近主体运动。R89 中去掉差分后 Confirm 仍为 `+0.004108`，所以原始差分没有独立证据；这正是要改成配准残差的理由，而不是重复使用原始差分。
- **学习空间图而非标量**是与 R90 有实质区别的最小结构变化。

### 必须修正

1. 不把 DOVER、FAST-VQA、显著性检测或动作识别的论文增益当作高光帧选择增益。它们的标签和指标不同，只能提供结构灵感。
2. 不把 100M 参数等同于低计算量。多视图若分别运行编码器，推理成本可能远高于当前模型；必须缓存和批量化，并报告实际 GPU 利用率、独帧数、显存和墙钟。
3. 不把 RGB 直接替换成高频图。ImageNet 预训练编码器的输入合同会被破坏。首个实验应保留 RGB 主干，再用参数极小的视图分支或投影层接入滤波图。
4. 不在没有目标域时间证据时把 ROI utility 放进时间排序。R82 已经说明公开空间效用跨域校准不足；ROI 先作为辅助视图，时间和空间输出仍固定为 R54/R70 的已审计合同。
5. 不把 PHD/GIF 的未选中区间全部当可靠负例。已知 `gif_hard` 占位字段必须隔离，使用真实区间 union、来源级划分和缺失状态记录。

## 最小判别实验（建议编号 R92，尚未运行）

### 固定条件

- 训练/验证只使用公开 PHD2/GIF 的源级留出；不得读取 AIC 官方测试标签或用官方回分调参数。
- 时间输出使用原始 frame ID，解码阶段保持 R54 的精确每视频预算；空间框逐帧固定为 R54 或 R70 已审计输出。
- 先使用冻结轻量 RGB 语义主干（ResNet18 或同一已审计小模型），只训练轻量时序 head 和视图投影；总实际推理参数单独列清。
- 所有变体相同源划分、seed、训练步数、目标和预算。评价以源级宏平均集合效用/固定 keep 代理为主，同时记录帧命中、集合交集、校准和视频级 delta。

### 变体

| 变体 | 输入 | 目的 |
|---|---|---|
| R92-A | RGB 主干 + 时序 head | 必要基线，不能用 R90 的 ridge 代理代替 |
| R92-B | A + 低频（Gaussian/下采样）图 | 检验大尺度布局是否有独立增量 |
| R92-C | A + 高频（Laplacian/Sobel）图 | 检验局部结构/清晰度是否有独立增量 |
| R92-D | A + 全局运动补偿残差图 | 检验主体变化而非相机运动 |
| R92-E | A + B+C+D，并用 gated fusion | 检验多视图互补而非单视图偶然收益 |
| R92-F | E，但对运动视图做源内时间置换 | 判别模型是否使用了时序对应关系 |

首版不加入 ROI utility 到时间分数；ROI 只可作为记录或后续条件视图。若 E 超过 A 且 F 的收益消失，才有证据认为多视图时序表征学到了可迁移的结构。

### 预先冻结的判别标准

- E 相对 A 在留出源上的集合效用增量至少达到 `+0.005`，且源级 bootstrap 95% CI 下界大于 0，才进入官方候选生成阶段。
- E 只提高训练集、在留出源不提高，判定为过拟合或监督错配；停止扩大视图数量。
- F 与 E 几乎相同，说明模型可能只使用运动能量/来源统计而没有使用时间对应；不制作官方包。
- B/C/D 各自无增量但 E 有增量，保留“联合关系”解释；若 E 也无增量，则关闭传统多视图时间路线，转回目标域监督或观测路径。

这个门是研究门，不是官方分数承诺。即使通过，也要在固定 R54/R70 空间合同下生成单一时间变量官方包，并将平台回分作为唯一最终验证。

## 工程实现要点

多视图数据必须按批处理，避免逐图 CPU 计算成为瓶颈：同一批帧先堆叠为 `[B,3,H,W]`，低/高频和配准残差在 GPU 或向量化 CPU 上一次生成，再一次送入轻量分支；缓存 `[video, original_frame_id]` 对应的特征，禁止按行号复用。实验日志至少记录 batch size、DataLoader workers、decode 时间、GPU 利用率、峰值显存和有效独帧数。

## 决策

1. 保留 R89 作为低成本空间先验候选，但不把其 `+0.004104 IoU` 折算为官方分数。
2. 不重复 R90 的低维 bank、未配准帧差和简单标量拼接。
3. 将“保留视图形状的多视图时序编码 + PHD/GIF 目标域监督”列为下一条新机制路线；先完成 R92-A/E/F 的最小闭环，再决定是否上 GPU 大实验。
4. 在 R92 通过前，不制作 ROI 驱动时间重排包，也不继续扫描 utility 融合权重。

## 证据边界

本报告支持的是“该实验尚未被已有 R89/R90 关闭”，不是“传统处理能够突破 40 分”。当前仍缺少：AIC 官方时间 GT、同一视频的公开时间与 native crop 联合标签、以及 R92 的源外结果和官方回分。
