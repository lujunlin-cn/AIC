## 一、oracle 与误差分解的实际定义（按代码复核）

来源：`scripts/teacher_diag_eval.py`，产物 `/data/aic/experiments/T1_T2_TEACHER_DIAG_V2/{metrics.json,keyframes.jsonl}`。

| 问题 | 实际定义 |
|---|---|
| confirm2 是什么 | RetargetVid（DHF1K 源）601–700，100 个源视频 × 1:3 / 3:1 两个比例，6 名标注者逐帧裁剪。16:9 源；1:3 窄窗 = x 轴滑动，3:1 高窗 = y 轴滑动 |
| IoU / 聚合 | 取整像素、含端点的 IoU；每帧对 6 名标注者**取平均**；视频内对全部帧平均；两个比例再平均成一个视频值；视频宏平均。相邻帧不作独立样本：CI 按源视频 bootstrap |
| 0.836（`ORACLE_FRAME_GRID65`） | 每帧从 65 个合法最大窗口位置里选**一个**使"6 人平均 IoU"最大的位置，每帧可以自由移动。是单一答案，可以被一个系统同时实现 |
| 逐标注者各自选最优窗 | 另算：0.98（dev/confirm2 相同）。这才是"输出多个互不一致答案"的乐观版本，此前报告没用它 |
| 0.706 / 0.699 | 每镜头一个恒定位置 / 每视频一个恒定位置的最优值 |
| 候选集合 | 仅 65 格网格（129 格为 0.838，离散化损失 0.002），不是连续空间的严格上界，只是该候选集合的参照 |
| 0.691 / 0.730 | 候选集 {B0, N0, P0, REGION} 每镜头 / 每帧取最好 |

需要更正此前报告的三处表述：

1. **"每镜头单窗上限约 0.70"不能约束 N0/DENSE。** 官方集上 N0 在 318 个可移动镜头里只有 6.3% 是静态的，每镜头中位 127.5 个不同位置、位置跨度中位为可移动范围的 19%；DENSE 为 141.5 个、21%。现有路径已经逐帧移动，0.70 只约束"每镜头一个窗"的系统。
2. **49% / 42% / 5% 不是互斥的因果贡献。** 这三个数只在"消费 Qwen 回复的关键帧"上算（confirm2 4,081 帧），按帧分类：`subject_miss` = 点落在不足一半标注者的 GT 窗内；`placement` = 点在窗内但以点为中心的窗比网格 oracle 低 0.1 以上；`ok` = 其余。份额 = 各类 (oracle − IoU) 之和 / 总和，**按关键帧池化**。三类互斥且合计 100%：miss 42.0%、placement 48.7%、ok 9.3%（此前没列的"约 4%"实际是 ok 类，即差距 < 0.1 的帧仍有 9.3% 的缺口）。0.1 阈值是固定选择，不是干预实验；没有顺序替换，谈不上交互。
3. **份额依赖池化方式和比例。** 改成先视频内再视频宏平均：miss 21.7%、placement 51.6%（ok 类在个别视频上分母接近 0，不稳定）。分比例：1:3 窄窗 miss 61.8% / placement 31.8%；3:1 miss 5.7% / placement 79.4%。所以"位置决策是最大单项"只在池化后成立，而且主要是 3:1（y 轴）的现象；1:3 窄窗的主要问题是主体认错。
4. **"传播约 5%"没有对应的份额计算。** 实际量是：dense-only 关键帧上"沿用 1 s 前的点"0.641 vs "新点"0.669（confirm2 3,888 帧），以及 N0 在关键帧 / 非关键帧上相对 oracle 的差距 0.193 / 0.189。

**赛事迁移限制**：官方集 119/174 是竖屏源 → 16:9（y 轴滑动，窗口占高度 31.6%），54 是横屏源 → 9:16（x 轴滑动，窗口占宽度 31.6%）；有脸帧 20.8%，65 个视频无任何人脸帧。RetargetVid 的 1:3（窗宽 18.8%）和 3:1 与这两种几何都不同。LIVE-YT-VC（1920×1080 → 竖屏）的窗口比例恰为 0.316，与官方横屏源几何一致，但只有 x 轴、单标注者、30 个稀疏帧。

## 二、T5 候选评分器

预注册 `configs/T5_CROPHEAD_V3_PREREG.json`（sha 在 `/data/aic/experiments/T5_CROPHEAD_V3/prereg.sha256`）。母本 TEMP；固定 TEMP 掩码、N0 观察协议（1 s 关键帧 + 切点、640 px、冻结点提示 md5 998c3de9）、有脸分支、EMA、最大窗口；只改"关键帧点 → 窗口中心"的映射。

### 数据与划分（按源视频，不按帧）

| 集合 | 来源 | 单元 | 有 GT 的关键帧 | 用途 |
|---|---|---:|---:|---|
| rv_train | RetargetVid 001–080 × 2 比例 | 160 | 3,464 | 训练 |
| live_train | LIVE-YT-VC train（hash 折外） | 1,466 | 7,812 | 训练 |
| rv_dev / live_dev | RetargetVid 081–100 / LIVE train hash 折 | 40 / 156 | 746 / 800 | 选 H1/H2、选轴 |
| **live_confirm3** | LIVE-YT-VC val，从未使用 | 178 | 913 | 主确认（x 轴） |
| rv_confirm2 | RetargetVid 601–700 | 200 | 4,081 | y 轴确认（此前用于 T1/T2 决策，但从未用于拟合/选择本评分器，证据较弱） |

LIVE 的 1,800 个视频新建了观测缓存（GPU2），并用冻结点提示跑了 1 s 关键帧点（178 + 1,622 个视频，约 1.95 s/视频，GPU 4–7）。LIVE 每视频只有 30 个稀疏人工帧、单标注者，且框大小可变，这里只用最大窗口的 IoU 评价。候选 = 65 个合法位置 + N0 位置；目标 = 该关键帧的标注者平均 IoU。

### 候选 oracle（关键帧上，GT 选最优）

| 集合 | N0 窗口 | 65 格 oracle |
|---|---:|---:|
| rv_confirm2 x 轴（1:3） | 0.557 | 0.777 |
| rv_confirm2 y 轴（3:1） | 0.777 | 0.889 |
| live_confirm3 x 轴（9:16） | 0.534 | 0.769 |

把关键帧 oracle 放进完整管线（保持 + EMA + 有脸门控）后只剩 +0.10（rv_confirm2）/ +0.019（live_confirm3）：LIVE 视频短（约 6 s、1 s 关键帧）、非关键帧多，关键帧上的改进只能部分传播，这是本方法在 LIVE 上的可学空间上限。

### 结果（完整管线，相对 H0 = N0，视频 bootstrap）

| 模型 | rv_dev | live_dev | **live_confirm3** | rv_confirm2 | rv_confirm2 x / y |
|---|---:|---:|---:|---:|---:|
| H1 几何校准（4 个标量） | +0.0176 | +0.0074 | **+0.0062 [+.0034,+.0093]** | +0.0148 [+.0097,+.0200] | +0.0118 / +0.0179 |
| H2 MLP seed0 | +0.0176 | +0.0059 | +0.0043 [+.0018,+.0070] | +0.0098 | +0.0013 / +0.0183 |
| H2 MLP seed1 | +0.0155 | +0.0029 | +0.0017 | +0.0093 | — |
| 关键帧 oracle | +0.0874 | +0.0159 | +0.0191 | +0.1007 | +0.128 / +0.073 |

- dev 上 H1（数据集等权 +0.0125）≥ H2（+0.0118 / +0.0092），**按规则选 H1**，两个轴的 dev 增益都 > 0，都应用。
- H1 拟合值：x 轴 a=0.85、b=+0.025；y 轴 a=0.65、b=+0.025。含义是把以点为中心的窗向画面中心收 15% / 35%，再沿滑动方向偏移 2.5% 窗长。
- 确认：live_confirm3 +0.0062，CI 下限 > 0；x 轴、y 轴的各自确认也都 > 0。**满足晋级条件**。H1 是确定性网格拟合，第二个 seed 结果完全相同；H2 在第二个 seed 上更弱，说明小神经头的额外容量在这批数据上没有稳定收益。
- 量级：LIVE 的 +0.006 约为 N0−B0 在 confirm2（+0.034）的 1/5，大约吃到关键帧 oracle 管线空间（+0.019）的三分之一。

### 回答"位置决策缺口能否被外部人工监督学到"

能学到一小部分，而且是可以跨源迁移的系统性偏差（"语义点偏离人工构图中心，人工裁剪更靠近画面中心"），用 4 个标量就能拿到，神经头没有更好。关键帧上的大部分 oracle 缺口（x 轴 0.56→0.78）没有被当前推理特征解释；它更可能需要更好的观察（例如主体范围、多主体取舍），而不是更复杂的映射。
