## 0. 一页纸摘要

我们卡在 **34 分**。八轮迭代、17 条官方打分记录，从 53K 参数的 YuNet 到 33B 参数的教师模型，全部落在 33.8–34.9 的一分窄带里。

**通过把评分公式做数值分解，我们定位了瓶颈不在模型能力，而在评分函数的分母**：

```
F1_video = 2 · Σ_{命中帧} IoU / (N_pred + N_gt)
```

- 我们预测**全部帧**（N_pred ≈ 550/视频），而 GT 只标注约 39% 的高光帧
- 保留一个非高光帧**只增加分母、不增加分子**
- 数值上：全帧预测 = 0.34 F1 = 34 分；完美排序且只留高光帧 = 0.62 F1 = 62 分
- **剩余约 28 分空间全部来自"更准地判断哪些帧值得保留"（时间排序精度）**

但我们进一步发现：**这个空间被一个更深的问题锁死了**——打分器缺少概率校准，导致所有依赖绝对概率的决策规则（自适应阈值、期望 F1 优化、跨视频预算分配）都无法工作。详见 §7 的一次失败实验。

## 1. 任务与评分机制的精确描述

### 1.1 数据集（复赛 drop）
- **426 个 YouTube 短视频**，任务是"gif 高光"（来自 PHD² 域：YouTube 视频 + 人工制作的 GIF）
- 时长：中位 **14.1 秒**（p10=7s, p90=36s），总帧数 median≈550/视频
- 方向：66% 横屏 16:9 / 29% 竖屏 9:16
- 关键帧在 1 秒网格上（视频 0 是 60fps，step=60，即每秒一帧）

### 1.2 每帧的输出
该帧上"最值得保留的裁剪窗口"，格式 `[x, y, width]`（**注意：是左上角坐标，不是中心**——这个坑让我们一度把包级 IoU 从 0.997 误算成 0.72），高度由目标比例推出：`h = w · rh / rw`。滑窗沿长边自由滑动，短边贴齐。

### 1.3 评分（我方复刻，与平台一致）
```python
# aic/evaluation.py
for prediction in predictions:
    if validate(...) and frame not in used:
        if frame in truth:                      # 只有帧号命中才算
            iou_sum += box_iou(pred_box, gt_box)
f1 = 2 * iou_sum / (n_pred + n_gt)             # 逐视频
score = 100 * mean(f1_per_video) * k_size      # macro 平均
```

**k_size 阶梯**（模型大小 → 系数）：≤100MB→1.00 / 100–500MB→0.95 / 500MB–9GB→0.90 / >9GB 超限。

**四条结构性事实**：
1. GT 只标注高光帧，**不是每帧都有 GT**（PHD² 域实测正例率 p≈0.39）
2. `N_pred` = 提交的预测帧数，**预测全部帧会让分母最大**
3. 保留非高光帧 = 纯增分母
4. 计分是 **macro**（逐视频 F1 再平均）

### 1.4 数值分解（这个表是全部后续推理的基石）

设 p = 高光帧占比 = 0.39，m = 命中帧的框 IoU = 0.62：

| 策略 | F1 | 分数 |
|---|---|---|
| 预测全部帧 | `2mp/(1+p)` = **0.343** | **34** |
| keep=0.80 | ≈0.36 | 36 |
| keep=p 且完美排序 | `m` = **0.62** | **62** |

**当前 34 分 ≈ "全帧预测 @ p=0.39, m=0.62" 的理论位置，完全自洽。** 这不是巧合，是诊断的确证。

## 2. 八轮迭代：什么有效、什么无效

### 2.1 官方打分记录（registry，17 条）

| 包 | 模型 | 平台分 |
|---|---|---|
| B0（YuNet 人脸跟随）| 53K 参数 | 31.58 |
| V7 空间头 | 450M | 33.82 |
| V8 B3 空间头（多几何训练）| 450M | 34.75 |
| V8 B3 + 时间掩码 keep=0.80 | 450M + TCN | **34.88**（当前最高学生包）|
| 32B 教师（Qwen3-VL）| 33B | 34.84 |
| V9 A1raw（+PHD² KD 蒸馏）| 450M | （与 B3 同预测集，头不同）|
| V9 VisionOnly（剥离 LM）| 450M→170MB 声明 | 34.73 |

**全部挤在 33.8–34.9。** 唯一离群的是最简单的 YuNet（31.58）。

### 2.2 迁移矩阵（哪些机制有效）

对八轮实验做"机制 × 是否跨域正迁移"的统计（Fisher 检验 p≈0.002）：

- **教师点位 / 时间掩码类：5/5 正迁移**（+8.41 / +0.93 / +4.01 / +1.04 / +0.79）
- **空间几何 / 学习类：0/6**（缩放 −4 / 居中 −4.29 / XRERANK −0.18 / T5 −1.84 / H1 −0.11）

**规律**：只有"教师直接给点位/掩码"的机制才正迁移；"让模型自己学空间决策"的机制全部失败。原因是本地验证集在空间轴上事实性失效。

### 2.3 关键负结果（都有平台分背书）

| 实验 | 本地指标 | 平台结果 | 教训 |
|---|---|---|---|
| PHD² 教师点位 KD 蒸馏 | confirm +0.018（显著）| 未改善 | **本地池的方向性失效**：本地正、平台负 |
| QVHighlights 辅助域时间头 | QV 域内 AP 0.809 | — | **跨域迁移失败**（见 §6）|
| 融合 QV 头 + 原生头 | — | — | 融合比原生头**更差**（0.338 vs 0.356）|
| 剥离语言模型降 k_size | — | 34.73 vs 34.75 | **平台按物理文件大小核验**，此路不通 |
| 降 KD 权重（0.15/0.30）| 域内增益减半 | — | 域增益与权重单调，无 trade-off |

**元教训：本地验证集的"正迁移"在官方集上可能是负的。** 空间学习 0/6 是第一次，KD 蒸馏是第二次，QV 跨域是第三次。**三次都指向同一个问题——我们没有一个真正对齐官方分布的验证集。**

## 4. 技术栈与关键实现

- **硬件**：Ascend 910A × 8（aic-batch 容器见逻辑卡 0–5 = 物理 2–7）
- **推理栈**：transformers 5.1 + torch_npu 2.10 + CANN 9.0；**必须 `attn_implementation='eager'`**（默认后端调用 `aclnnIsNegInf`，910A 不支持，EZ1001）
- **视觉塔**：LFM2.5-VL-450M 内嵌的 Siglip2 NaFlex（85.8M 参数），冻结
- **学生空间头**：2305→512→128 MLP + 2 层自注意力，1,511,425 参数，129 个候选窗口
- **学生时间头**：3 块膨胀 TCN（dils=[1,2,4]，感受野 15 帧），约 197K 参数
- **教师**：Qwen3-VL-32B，批量 transformers 推理 0.65 qps（不用 vllm——vllm-ascend 缺 FusedInferAttentionScore）

### 踩过的坑（都有复用价值）
1. **`container.seek()` 的 offset 是 stream.time_base 的 tick**：`offset = seconds / time_base`，用 `*` 会截断成 0 导致解码全空
2. **35% PHD² 是 AV1**，OpenCV 无 libdav1d，必须用 PyAV 18
3. **`to_empty()` 构造模型**会让 Siglip2 的 `position_ids`（non-persistent buffer）变垃圾 → 触发 `aclnnIsNegInf` 崩溃；必须 CPU 真实构造
4. **BLAS 线程失控**：8 workers × 24 核 = load 965，把并发跑的教师从 12s/批拖到 33s/批；必须在 `import numpy` **之前**钉线程数
5. **bbox 格式**：`[x,y,w]` 是**左上角**不是中心
6. **进程组会被 reap**：launcher 用 `setsid nohup` + POLL 循环，否则整组被杀
7. **标签判定的浮点边界**：半开区间比较会静默丢弃所有"边缘裁剪"的标注——一次就让时间池丢了 84% 的数据

## 6. QVHighlights 辅助域：域内强，跨域无效（完整案例）

这是最近一次完整的新增域尝试，值得完整记录，因为它揭示了一个反复出现的模式。

**动机**：官方集 37.3% 视频空间无决策（分数全靠时间轴），而时间轴六轮没动。QVHighlights 提供 22 标注者的**密集无 query saliency**（0–4 分/clip），比 PHD² 的二值区间信息密度高一个量级。

**全量管线（已建成，可复用）**：
1. `v10_qvh_labels.py`：官方 release 标注 → 1Hz 网格（`saliency` 标注者均值 + `soft` 指数距离软标签 + `n_annot` 置信权重）。train 7,100 / val 1,519 / test 1,529 视频
2. `v10_qvh_extract.py`：PyAV 抽帧（**坑**：HF 镜像的 bucket 目录是**小写首字符**但文件名保留原始大小写，大写 vid 第一版全部 missing 80%）
3. `v10_qvh_feats.py`：vision tower pooled `[T,768]`
4. `v10_qvh_fragment_index.py`：150s 切成 8–14s 片段（65% 锚高光区间 / 35% 随机，复用 PHD² 同口径），**均值 11.0s 对齐官方 14.1s**
5. `v10_qvh_frag_tcn.py`：多尺度 TCN（RF=63）

**结果**：
- **域内**：9,000 片段，三 seed val AP **0.809 / 0.782 / 0.789**（base 0.74–0.78）——确实学到了信号
- **跨域到 PHD²**：AP 掉到 **0.531**（原生头 0.695）
- **keep 掩码模拟**（3,958 片段 / 1,987 源）：

| 头 | 峰值 F1 | keep | vs 同预算随机 | 显著性 |
|---|---|---|---|---|
| native | **0.3561** | 0.70–0.80 | +0.055 | CI 全显著 |
| QV | 0.3203 | 0.85 | +0.004 | **CI 全跨0（无效）** |
| fusion | 0.3383 | 0.70–0.80 | +0.044 | 显著但**低于 native** |

**结论：QV 头做 keep mask 无效，融合反而拖累原生头。** 域内强 ≠ 跨域可用。

**副产品**：全量 keep 扫描显示峰值在 0.70–0.80，正是已提交包（keep=0.80）的值——**keep 率这条杠杆已用尽**。

## 7. 突破尝试：自适应 keep 与一次重要的自我纠正

### 7.1 想法
F1 最优的逐视频保留帧数不是常数。F-measure 最优化的经典结论：按概率排序后保留 `p_i > F*/2` 的项，最优切点是不动点。我们的头只做了排序训练，输出不校准——但我们想试试能否用打分器自己的分数做自适应。

### 7.2 第一版结果（+0.075，看起来是突破）
```
fixed_0.80:  F1 = 0.3977
adaptive:    F1 = 0.4727      ← +0.075, CI [+0.072, +0.078]
adaptive keep 率: 均值 0.56, p10=0.25, p90=0.875（跨视频差异巨大）
```

### 7.3 复查：这是信息泄漏
代码里自适应规则用 `adaptive_mask(p, iou, n_gt)`，其中 `iou = where(y>0, 0.62, 0)` 依赖真实标签 `y`，`n_gt = int(y.sum())` 是真实正例数。**等于把答案喂给了决策规则。**

### 7.4 无泄漏重跑
规则只用打分器自己的输出（`n_gt ≈ Σp`，`E[iou] = 常数`）：
```
fixed_0.80:    F1 = 0.3977
adaptive:      F1 = 0.3696     ← −0.028, CI 跨0
adaptive keep 率: 恒为 1.0（全部保留，规则退化）
```

### 7.5 这个失败定位了真缺口
自适应规则退化成全选，因为 min-max 归一化后的 `Σp ≈ L`，推出的"估计正例数"过大 → "多保留不吃亏"总成立。

**根因：打分器没有校准。** 它只做了排序（MSE 回归到 in-interval 标签），sigmoid 输出既不校准、也不跨视频可比。**任何依赖绝对概率的决策规则（自适应阈值、期望 F1 优化、跨视频预算分配）目前都无法工作。**

这是我们此前从未意识到的一环——八轮实验都在优化"排序"，从没想过"概率"。

## 8. 当前在跑的三条线（V10，`v10_stage2_master.sh` 自主运行）

全部针对**帧级排序判别力**（真瓶颈），教师完成后自动启动：

| 线 | 假设 | 做法 |
|---|---|---|
| **1 特征** | mean-pooling 无法区分"主体占满画面"与"主体占 5%"——keep 决策的分界恰在此 | 重池化 mean + **attn**（固定 query 注意力池化）+ **topk**（L2 范数最高的 48 token）|
| **2 结构** | 单尺度 RF=15 覆盖不了官方 p50 14s 片段 | 单尺度 vs **多尺度并行分支** RF=63，2 seed |
| **3 数据** | 只有 674 个有正负例的高光片段 | 用**实际关键帧时间戳**（非理想网格）重建池；剔除全正片段（无排序信号）|

**判定门槛**：矩阵按 val AP 排名，但**只有 keep 曲线上 F1 显著优于同预算随机的高分臂才可出包**（AP 赢但 F1 不赢的不发）。

## 9. 给后续研究者的建议清单

**已被证伪，不要重试**：
- 更大的骨干 / 更好的特征提取器
- k_size 系数套利（平台按物理文件核验）
- 跨域蒸馏（KD 教师点位、QV 辅助域）——三次尝试全部失败
- 空间学习类机制（0/6 负迁移）
- 固定 keep 率扫描（已在 0.70–0.80 找到峰值）

**值得深挖**：
1. **概率校准**（§7 揭示的缺口）——一旦有校准，自适应决策/EM-F 优化才可行
2. **macro F1 的逐视频结构**——某些视频全删、某些全留是否占优？
3. **排序 AUC 与框 IoU 的边际收益权衡**——哪个更值得投？
4. **PHD² GIF 标签的噪声本质**——"人类觉得值得做 GIF"与评测"精彩帧"是否同源？
5. **≤100MB 直接吃 k_size=1.00 档**——极端量化的精度损失 vs +11% 系数

**方法论教训**（我们错了三次）：
- 性能上"突破了"时，第一反应应是**找泄漏**（尤其是增量来自"更聪明的规则"而模型没变时）
- **本地验证集的方向性失效是系统性的**，三次跨域/跨机制尝试全部被平台打脸
- **分数口径**要先确认（我们曾把平台分除以 k_size 得出"raw 38.76"的虚构结论，误导了整轮决策）
