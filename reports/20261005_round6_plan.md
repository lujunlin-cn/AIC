## 0. 对 R6 计划的本地审查结论

统计单位（源簇 bootstrap、每臂 3 种子、至多 2 个主比较）全部与本项目纪律一致。
硬件名称核对：npu-smi 确认卡为 910B，物理 2-7 共 6 张可用（0,1 他人进程不碰）。

两个 48h 探针的可行性已用本地数据实测核验（2026-10-05 盘点）：

| R6 前提 | 本地核验结果 | 判定 |
|---|---|---|
| LIVE 一次性确认池 ≥120 源 | **val_index 178 源：从未进训练索引、从未被任何开发/确认读取触碰**（train 1622 ∪ val 178 = 1800 全量；已暴露 351 源全部 ⊆ train_index） | 可行，不触发 BLOCKED_FRESH_SPATIAL_CONFIRM |

| T-TOKENS 复用已验证契约 | native 帧契约 ac3b657f + 构建器在库；native 线关闭的重开条件即"特征定义变更"，池化前跨层读取满足 | 可行，按条件预算 |

需本地化执行的修正（不改变计划结构）：
1. S-REREAD 试验规模（240 训练/80 开发/12 候选每帧）先过两道实测：
   100 张候选裁剪图编码吞吐 → 再定全量规模；短名单 oracle regret ≤0.01 门
   不过先扩候选，不归因评分器。
2. S-ZERO 的 λ 网格严格预注册 {0, 0.25, 1}，确认集上不选 λ。
3. GPT 的"六张 910B"与实际一致；单任务 ≤12h 训练上限、BLAS 线程先限后跑照旧。

## 2. Phase P0（今天启动，CPU 为主 + ~2 NPU·h parity）

产出物全部落 `reports/r6/` 与 `experiments/20261005_v11/`：

   种子 3、源簇 CI、至多 2 个主比较、val178 一次性确认声明）。
2. **source_ledger.md**：LIVE 源级暴露台账（1622 train-index / 178 val 全新 /
   351 已暴露明细：dev 124 + confirmation 227 + rv 70）；val178 冻结为一次性
   确认池，访问写 confirmation_access_log.jsonl；RetargetVid NEW170 未用 ~100
   源登记为备选。
3. **label_projection_audit.json**（Q7-B）：用 native 契约原帧记录算
   e_proj、e_min、部分命中块比例、原帧 oracle vs 1 秒块 oracle 差、部署掩码 F。
   公式按 R6 §Q7-B，空集约定用项目评分器口径。
4. **xperm_intervention_audit.json**（Q7-A）：冻结 champion checkpoint 上 5 类
   对照（本视频 mu 重复 / 残差打乱 / mu+他视频残差 / 分层 derangement / 零输入）

6. **numeric_parity.json**：Siglip2 patch 在上的 CPU/NPU parity 重跑 +
   错误注入测试（时间错位、padding、布局、FP16 溢出四类注入至少各一）。

P0 全绿是 S/T 任何训练结论的前提；契约失败即 `INVALID_IMPLEMENTATION`。

## 3. Phase S：S-REREAD 主线 + S-ZERO 零参数对照（14 NPU·h）

机制：E(crop(I,b)) ≠ pool_b(E(I))。向编码器提供候选窗口的真实裁剪图，
是 S1（特征重组，判负）与 S4（分数平滑，判负）之外的第三条路，
直接攻击 S0 锁定的 0.247 候选选择差距。

步骤（按 R6 §Q3 协议，数量预注册）：
1. 24 开发视频候选图检查 → 100 张实测吞吐 → 定 240 训练/80 开发规模。
2. 短名单构建：B3 top-3 + 滑带 9 等距点，去重 ≤12 候选/帧；
   **短名单 oracle 门：相对全 129 候选平均损失 ≤0.01**，不过先扩候选。
3. 编码实际裁剪图（NPU 两卡，Siglip2 patch 在上）+ 重复全图对照 embedding。
4. CPU 四臂训练（新增可训练模块 ≤2M 参数，目标仍是标注者平均 IoU）：
   - S0 = 原 B3（正式基线）
   - S1-control = B3 输入 + 重复全图 embedding（同容量对照）
   - S2 = B3 输入 + 实际候选裁剪 embedding（残差形式）
   - S3-zero = B3 与候选—全图余弦相似度固定融合（零新参数，λ∈{0,0.25,1}）
5. 开发读（旧 dev/confirmation 只作开发）：S2 门 = IoU +0.03、配对 95% CI
   下界>0、同时胜 B3 与 S1-control；S-ZERO 门 = +0.02、CI 下界>0。
6. 过门者进 val178 一次性确认读（每候选组至多一次预注册读）。

失败条件照 R6：S2 不胜同容量全图对照 → 暂停该输入迁移，不推广到
"所有空间学习无效"；只有美学代理改善而真实 IoU 不动 → 暂停。

## 4. Phase T：T-CONTEXT 数据干预 + T-TOKENS 表示对照（12 NPU·h）

T-CONTEXT（主）：同一真实事件在合法片段的前/中/后多位置出现——
事件主体像素与顺序不变、上下文来自同一连续源、共享原帧标签同源。
2×2 设计：{历史切片协议, 事件多位置协议} × {健康 TCN, 稠密多尺度头}，
加位置基线对照；同一特征、同一帧级监督、匹配样本曝光量。
主门：新源原帧时间 macro F ≥ +0.007 vs 健康头与位置基线，配对 95% CI
下界>0，正例视频退化 ≤0.005。等变误差只作诊断不作门。

T-TOKENS（条件）：同一 VideoMAE 前向缓存最后层/倒数第 5 层/中间层，
池化前空间 token → 128 维投影 + 4 可学习查询 attention pooling，
对照容量匹配的重复末层均值。只有 T-CONTEXT 特征构建后预算有剩才跑；
AP 单独永不晋级。

## 8. 执行顺序（48h 墙钟目标）

0-4h：P0 全部六项（parity 与错误注入占 NPU ~2h）。
4-20h：S 编码两卡 + T 上下文构建 CPU 夜间；短名单 oracle 门裁定。
20-36h：CPU 四臂训练与开发读（S 线先裁定；T 线 2×2 完成训练）。
36-48h：过门者 val178 一次性确认；未过门不跑 426。
48h+：过门候选发布重放；官方名额按门消费，默认继续持有。
