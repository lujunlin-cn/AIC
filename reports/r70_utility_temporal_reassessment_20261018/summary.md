# R70 空间效用驱动时间重排复核（2026-10-18）

## 结论

空间效用驱动时间重排已经完成了第一轮机制验证，但还没有研究透彻，也没有官方分数证据。当前最关键的未闭环不是融合系数，而是效用变量与最终提交框的身份不一致。

R70 训练的是 129 个合法最大窗口的 native crop IoU。R72/R73 在时间排序时使用 R70 的最佳候选分数或其相对中心增益，但包内最终输出框来自 V9 B3。若 `j_V9(t)` 是 V9 实际输出对应的窗口，最终评分需要的空间项接近 `s_t = E[IoU(B_V9(t), B_t)|X_t]`，而当前 R72/R73 使用的是 `max_j s_{t,j}`。两者只有在 V9 框总是 R70 最佳候选时才相同。

## 已完成的证据

### 1. 公共 native crop 读出

同一 V9 特征、129 候选和 source-disjoint RetargetVid/LIVE 划分下，topsoft 读出相对中心候选的源级增量为 RV `+0.07121`、LIVE `+0.06892`，平均 `+0.07006`。这支持“候选效用中有可读空间信号”，不能直接证明官方联合分提升。

### 2. 绝对效用和边际效用不是同一目标

在 168 个公开留出源、1546 行上，用 topsoft head 的候选分数和 native crop GT 做诊断：

| 时间效用标量 | 与实际选中框 IoU 的 Spearman | 与实际边际增益 `IoU(argmax)-IoU(center)` 的 Spearman |
|---|---:|---:|
| `max_score` | 0.293 | 0.128 |
| `max_score-center_score` | -0.113 | **0.377** |
| `center_score` | 0.312 | -0.167 |
| `soft_expected_score` | **0.378** | 0.012 |

这说明 `max_score` 更像绝对 cropability，`max-center` 更像相对中心的改善；两者对时间选择会偏向不同帧。该实验没有时间高光 GT，因此只能区分空间效用语义，不能估计官方 F。

### 3. 当前效用与实际 V9 框存在明显错位

将 R70 关键帧的 129 候选分数线性插值到 V9 B3 全帧输出框位置后，8848 个关键帧的统计为：

- `output_utility - max_score` 均值 `-0.03886`，标准差 `0.08233`；
- 5% 分位 `-0.19475`，中位数约 `0`；
- 只有约 `56.5%` 的关键帧输出框与最佳候选分数相差小于 `0.001`；
- output utility 与 max utility 的相关系数 `0.821`，不是同一个量。

因此 R72/R73 的空间信号有约 43.5% 的关键帧没有对应到最终输出框。这个错位足以让一个在公开候选 IoU 上更好的空间头在联合时间决策中反而选错帧。

### 4. stable tie 会注入位置顺序

R73 使用 `max(max_score-center_score, 0)`。由于中心候选在 129 候选内，增益不会小于零；但约 44.7% 的官方关键帧增益恰好为零。原 `argsort` 对平值采用原始帧顺序，导致平值获得隐含的位置排名。

只把效用秩改为 exact-tie midrank，不改 R54 时间表达式、预算和空间框：

- R73 stable-rank：5004 次相对 R54 换帧，399 个视频变化；
- R74 tie-aware：2418 次换帧，245 个视频变化。

这不是官方收益证明，但它是一个确定的实现修正；R74 的 ZIP 和 independent checker 已通过。

## 新的输出对齐候选

### R76：输出框对齐的 additive utility

在每个 1 秒关键帧上，用 R70 的 129 个候选分数沿合法窗口偏移插值到 V9 B3 实际框位置，原始帧轴再插值；用 tie-aware utility rank 作为 R54 的固定 `.20` residual。只改变时间集合，V9 B3 框逐帧复制。

- 426/426 视频，199037 条预测，8.854531425B；
- 4251 次相对 R54 换帧；
- ZIP SHA `18d4986d84b705cd4076c4f640c77155eca5d1ac024583318fac0e7e3e7b2265`；
- independent checker 通过，未上传，官方分数未知。

### R77：输出框对齐的 multiplicative utility

在没有额外融合系数的情况下使用

```text
J_t = rank(T_t) * (0.5 + 0.5 * midrank(s_t))
```

其中 `s_t` 是上面的 V9 输出框效用。它更接近在 `T_t` 是高光概率、`s_t` 是条件空间 IoU 且二者条件独立时的 `E[Y_t IoU_t|X_t]`。仍然保留 R54 的准确预算和 V9 B3 框。

- 426/426 视频，199037 条预测，8.854531425B；
- 2308 次相对 R54 换帧；
- ZIP SHA `aae5cfa6ffc56e8276aa5aef741781143a23e71ca8f428a608228700aa7d4106`；
- independent checker 通过，未上传，官方分数未知。

R76/R77 仍不是联合 GT 验证：TimeLens 的 `T_t` 是中心与区间提示的秩代理，不是校准的 `P(Y_t=1|X_t)`；R70 output utility 也是从候选读出插值得到的部署框代理。两个必要识别条件都尚未成立。

## 仍然存在的主要提升点

1. **直接训练部署框效用头**：在公开 native crop 数据上先运行 V9 B3，直接以 `IoU(B_V9(t), B_GT)` 为标注训练一个 source-disjoint 标量 head。它比从 129 候选分数间接插值更贴合最终部署对象；成功后再在官方关键帧上推理并使用 R77 形式。
2. **时间项校准**：将 TimeLens 区间、中心先验和其它可用时间证据校准为源外的高光概率或相对期望贡献；当前中心秩不能被当成概率。
3. **关键帧观测 contract**：1 秒点到原始帧的线性插值会跨越切镜和短事件。下一次实验应做固定的 piecewise-hold/边界感知输出效用，对比必须预先确定，不能扫插值窗口。
4. **联合监督缺口**：公开空间 GT 与公开时间 GT 不在同一批视频上，人工 540 帧也不是 native crop GT。当前只能分别验证空间效用和时间排序，不能把两者代理分数相乘后称为官方 F。
5. **域迁移风险**：R70 的 RV/LIVE 增量是公开诊断；官方 426 的主体、画幅和标注政策可能不同。R70/R69/R71 的官方回分比任何本地代理更有识别价值。
