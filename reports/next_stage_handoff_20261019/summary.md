### 2.2 当前与历史规则显式分开

| 调用 | 行为 |
|---|---|
| 项目 `current`、`semifinal`、`semi-final` | 参数字段必填；0–9B；`Score=100*F_video` |
| 项目 `final`、`replay` | 保留历史 MB 与大小系数，便于复算旧结果 |

当前合同中的可选 `model_size_mb` 只作存储记录。

checker 只核对声明和调用方提供的计数，本次没有加载实际权重。
本地接受 0 参数算法，但不能用 0 隐去学习模型或缓存生成模型。

## 3. 条件性主攻：候选裁剪图像重新编码

**建议优先检验：保留当前时间集合，让空间模型读取真实候选裁剪图像，
并结合全图信息选择构图窗口。**

正式立项前必须读取 R84。如果 R84 已经覆盖真实候选重新编码，
本提案作废或根据 R84 证据修改。缺少这一步，不能声称该方向是新的。

### 3.1 它改变哪条路径

已核实的历史 B3：

```text
全图 → 冻结视觉塔 → 二维 token 网格
→ 候选窗内均值、窗外均值、差值与位置 → 候选效用
```

拟检验的路径：

```text
同一原生图像 → 按同一候选框截取真实图像 → 共享视觉塔重新编码
→ 候选局部信息 + 全图信息 + 原有位置 → 候选效用
```

这次改变是**视觉信息进入评分头的路径**。
候选 crop 在重新编码前获得局部采样分辨率，布局和边界信息可以进入模型。
实际能否改善错误尚未验证；不能仅凭结构就断言均值池化是瓶颈。

保持不变：R71 的逐视频选帧集合与预算、候选框集合、目标比例、
人工构图监督、数据源划分、输出坐标约定和时间后处理。
训练配置由 R84 最新可复现配置确定后一次冻结，不按官方回分搜索。

### 3.2 为什么暂时优先空间信息路径

B3 已经使用 129 个候选、2305 维 win/out 特征、MLP 与两层 self-attention。
监督已经是人工框的平均 IoU，骨干冻结、仅 head 训练。
所以候选 utility、expected IoU、增加位置或换小型读出都不能当新机制。
来源：[B3 合同](../r29/pipeline_contract.md)、
[B3 配置](../../configs/LFM_V8_B3_SEMIFINAL.json)。
源码也核对了观察路径：[特征提取](../../scripts/v9_phd2_lfm_feats.py)
对完整关键帧调用一次视觉塔并保存网格；
[空间训练](../../scripts/v8_s_train_multidata.py) 从缓存网格取候选窗内外均值。
因此，相对这份可核实的 B3，真实候选图像重新编码确实增加了观察；
这项结论不扩展到尚未取得的 R84。

空间侧有直接的人工构图监督。时间侧的公共摘要、重播行为和主观等级
不能直接等同赛事逐帧高光目标。用户又报告 R83 小数据策略失败。
这支持优先审查空间信息增量，但不足以证明时间方向已无价值。

历史 R17 的 fractional pooling 已有负结果。
本提案要求从真实 crop 增加观察，不原样重做池化细调。
RV/LIVE 的历史候选 oracle gap 也不能作为可学增益或官方涨分预测。
来源：[空间审查](../r29/spatial_review.md)。

### 3.3 与 40 分的关系

当前用户报告的最佳为 36.43，距离 40 差 3.57 分。
若完全固定 R71 的时间集合，每视频的预测数与真实标注数均不变。
按官方公式，要到 40，需要宏平均加权 IoU 贡献相对提高约
`40/36.43-1 = 9.80%`。

这只是固定时间集合下的代数要求。
它没有识别测试 GT、类别密度或某个数据集 IoU 到官方分的映射。
当前没有证据保证本提案能达到该增幅。

## 5. 最小判别实验

状态：**预案，未执行**。先恢复 R83/R84 与权重合同，再冻结具体配置和哈希。

### 5.1 三臂与一次破坏性诊断

| 臂 | 输入与训练 | 竞争解释 |
|---|---|---|
| A：当前已评分空间控制 | 准确恢复 R71 实际使用的空间链路，固定其时间集合 | 防止与过时 B3 或未评分候选比较造成虚假进步 |
| B：容量匹配、旧观察 | 与 C 相同 head 容量；附加分支只接收旧特征的固定投影 | 排除新增参数、优化预算与几何先验解释 |
| C：真实候选新观察 | 与 B 同候选、同监督、同容量；附加分支改接真实 crop 编码 | 检验局部图像信息增量 |

B/C 的候选数、框坐标、训练步数、batch、优化器、初始 head 规则和 seed 成对固定。
先用两个事先登记的 seed；不按结果更换 seed，不增加参数网格。
视觉塔先共享并冻结，使变化限制在观察路径。
R84 尚未官方评分，不替代 A。若 R84 可复现，增加其冻结输出作已有工作的对照，
并检查 C 是否只是重做 R84；不因为 R84 较新就称其为安全基线。

C 若优于 B，追加一次冻结权重诊断：在同视频候选之间打乱局部分支输入，
位置和候选框不动。若收益保留，不支持“对应候选的局部内容产生收益”的解释。
若收益消失，只构成机制支持；打乱也会制造分布变化，不单凭此项认定因果闭环。

### 5.2 预算与读数

先用固定公共训练帧做真实解码、坐标往返和特征对应 smoke。
smoke 只检验工程，不因少量样本的负结果否定整个方向。
测出每候选编码吞吐与显存后，冻结可在单次 12 小时内完成的正式数据量。
优先使用已有 LIVE 训练来源，不再以 12 源主观标注训练一个 interval policy。

正式报告保留每源 mean annotator IoU、同候选选择 regret、
TRAIN/DEV 差值、原生 x/y 轴与近/远中心分层。
按源 bootstrap，不将帧视为独立样本。
已有 DEV 暴露，因此区间仅作配对不确定性描述，不称无偏确认。

预案中的工程进展门为：两个 seed 的 C−B 平均 IoU 均至少 +0.01，
源级配对 95% 区间下界均大于 0，且至少 2/3 DEV 源不退步。
同时要求 C−A 在相同公共样本上也达到上述门。
C−B 只检验信息增量；如果 C、B 都弱于 A，不形成升级候选。
这是一次冻结的资源分配门，不是官方 40 分的代理门。
数据/配置正式冻结前可因合法样本覆盖修订；看过结果后不得降低门槛。

native y 轴若没有合法监督，保持该轴当前已验证策略，不宣称已解决原生竖屏。
若 C 只在训练源改善，则停止当前读出配方，不继续扩 head 或延长训练。

## 6. 参数、复现与提交条件

共享同一视觉塔执行全图和 crop 多次前向，参数只计一次。
但多次前向会增加计算；显存、吞吐与全量时间必须实测。
新增 head、保留的 R71 时间模型、空间 fallback、检测等全部进入参数账本。
R71/R84 完整组成未取得，因此本报告不填造新的实际参数总数。

训练前检查已授权设备的占用，不杀其他任务。
正式训练须使用现有 `<12h` 限制及超时保护，例如：

```bash
timeout --signal=TERM --kill-after=180s 42600s TRAINING_COMMAND
```

该命令为未执行模板；`TRAINING_COMMAND` 必须换成冻结的训练入口。
不能用分段改名重启同一训练来规避总墙钟上限。

形成比赛包前必须同时满足：

1. 绑定最新代码、数据 manifest、权重 SHA 和参数数。
2. 在合法公共源上完成冻结对照和失败分析；C−B 与 C−A 均过预设门。
3. 从原视频实际运行当前模型，核对帧与坐标合同。
4. 固定 R71 时间集合，逐视频逐帧核对 mask 无变化。
5. 完成当前索引全部视频的自动推理，不手改预测。
6. 在只读 ZIP 入口通过两套当前 checker，保存哈希。
7. 记录原视频重现范围、数值容差和全部 fallback。

官方上传另行决定，本轮不自动上传。
checker 通过只代表格式与提供的参数声明通过，不代表超过 40。
