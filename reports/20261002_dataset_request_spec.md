# 数据集补充需求规格（可直接派给其他 agent 去找）

**背景**：AIC 视频高光检测赛复赛。核心瓶颈已定位为**时间轴**——评分 `F1 = 2·Σ(matched IoU)/(N_pred + N_gt)`，我们目前预测全部帧（N_pred≈550/视频）而 GT 高光帧只占 ~30–40%，分母被撑大导致 F1 卡在 34 分（理论上限约 60 分）。要突破必须把"哪些帧是高光"判对。

**当前已有**：PHD²（同域，但只有稀疏高光区间）、QVHighlights（辅助域，22 标注者无 query 强度分，已在用）。**缺的是：与官方集同域（YouTube 短视频）且帧级密集标注的数据。**

---

## 硬性要求（不满足的一律不要）

1. **无 query 条件的帧级/片段级重要性标注**（关键，排除项见下）
   - 要的是"客观上这段/这帧精彩/高光"的独立评分或高光区间
   - **不接受**：只给"某 query 对应的时刻"的 moment retrieval / moment localization 标注（如 DiDeMo、MomentSeeker、QVHighlights 的 query 相关部分）——它们标的是"被问到/被描述的时刻"，不是"客观精彩帧"，监督有 query 偏置。
2. **视频已解包为可解码的 mp4**（不接受只给 tar 分卷压缩包；压缩包要注明完整性和解包命令）
3. **视频时长分布接近 5–30s**（官方复赛集 p50=14.1s；100s+ 长视频可以做但优先级低，因为我方会切片）
4. **域接近 YouTube 真实短视频**（竖屏 9:16 与横屏 16:9 都要有，官方集 66% 横 / 29% 竖）
5. 标注要能给出**帧号或秒级区间**（我方按 1s 网格对齐）
6. 许可可用于非商业研究（登记时注明）

## 加分项

- 帧级连续强度分（不是只有二值区间）
- 多标注者投票（能算置信度）
- 规模 >1,000 视频

## 明确排除（已评估，不要再找）

| 数据集 | 排除原因 |
|---|---|
| DiDeMo / MomentSeeker | query-conditioned 时刻定位，监督带 query 偏置；视频还是未解包 tar 分卷 |
| FCDB / FLMS / CPC / GAICD | 静态图像构图裁剪，我方空间学习轴 8 轮 0/6 迁移（Fisher p≈0.002），是已证伪方向 |
| TVSum / SumMe | 视频摘要数据集，帧级回归分数稀疏（每视频仅 1 个 rank 序列），非高光区间；且视频源多为长节目片段，域不匹配。**优先级低** |
| YouTubeHighlights | 已在盘（419/550 视频，963 标注），量小；可作为补充但不是缺口 |

## 如果找不到完全匹配的，以下是"次优但可接受"的两个方向

**方向 A：密集帧级 saliency/显著性数据集（任意域）**
- 要求：逐帧或逐 0.5–2s 的 0–1 连续显著性/注意力分，**无 query**
- 候选参考：DHF1K（已在盘，1,000 视频帧级显著性）、DAVSOD（已在盘，显著性+注视点）、Salicon、MIT1003、AUBWatch
- 说明：DHF1K/DAVSOD 我方已有，若有新的（如 Salicon 类大规模静态图像显著性，可转成伪时序）可以考虑

**方向 B：短视频高光/精彩片段检测（YouTube 域）**
- 要求：YouTube 短视频，带帧级或片段级高光标注
- 候选参考：YouTube-8M Highlights、Highlights 数据集集合（`yt8m-highlights`）、Video2GIF 用户行为数据、Reddit TIFU/FB highlights
- 说明：YouTube-8M Highlights 是 YouTube 域高光，最接近官方集，但每视频仅 1-3 个高光标注，稀疏

## 已排除的"伪需求"

不要找：更大的语言模型权重、更强的通用视频编码器、更大规模的视频分类预训练集——我方瓶颈是**标注形态**（缺帧级高光信号），不是模型容量。当前 vision tower（Siglip2 NaFlex，LFM2.5-VL-450M 内嵌）的 pooled 特征在本地池上已有判别力（IoU 0.55–0.73），不是特征质量问题。
