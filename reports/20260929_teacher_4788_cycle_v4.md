The three spatial packages come from three mechanisms. Each is compared against DT_V3 separately, and they are not stacked. Their public gains overlap heavily:

- Interpolation on top of 0.25 s: only +.0057.

The official set has 119 y-axis videos, which are portrait → 16:9 with a window of 31.6% of the height, and no public human labels have that geometry. The x-axis evidence is closer to the official geometry: LIVE-YT-VC has the same .316 window as the official x-axis videos.

## 8. E4: visual crop re-ranking pilot (`V4_E4_RERANK`, rejected on confirm2)

- Prereg: `configs/V4_E4_CROP_RERANK_PREREG.json`. It is the optional pilot from guide §9, started after the E2 main experiment finished.
- Candidates:
  - Fixed-size legal windows at c0 + d·win, with d ∈ {−.8, −.4, 0, .4, .8}, where c0 is the DENSE window. After de-duplication there are 3–5 candidates.
  - The 32B model sees the full frame plus the actual crops.
  - Each keyframe is asked twice: in spatial order, then reversed. A pick is used only if both orders agree; otherwise the DENSE point stays.
- dev2 run: 10,448 queries, 3,272 s.

| dev2 (70 videos) | Result |
|---|---|
| Pipeline RERANKNF − DENSENF | **+.0093 [+.0019,+.0173]**, 35 better / 28 worse, worst video −.057 |
| x axis | +.0174 [+.0064,+.0303] |
| y axis | +.0012 [−.0081,+.0124] |
| Keyframes: DENSE / selected / candidate oracle | .704 / .712 / .778 |
| Order agreement | 79%; 82% of agreed picks equal the DENSE window |
| Position bias | First label picked in 6.3% / 5.0% of cases (orders 0 / 1); no first-position bias |

Oracle and selector, separately:
- The candidate oracle (best single window per frame by mean-annotator IoU) is +.074 above DENSE.
- The selector captures only +.008.
- By axis:
  - x axis: captures 16% of the oracle gain. When it moves the window, 67% of moves improve IoU, with a mean gain of +.115.
  - y axis: captures −12%. When it moves the window, 59% of moves make IoU worse.
- So the bottleneck is the selector. On the y axis (RV 3:1, large window) the model cannot tell candidates apart.

| confirm2 (100, reused) | Result |
|---|---|
| Pipeline RERANKNF − DENSENF | +.0072 [**−.0011**, +.0161], 51 better / 39 worse, worst video −.127 |
| x axis | +.0179 [+.0074, +.0314] |

| Keyframes: DENSE / selected / candidate oracle | .664 / .674 / .758 |

Decision:
- confirm2 fails the prereg rule twice: the CI lower bound crosses 0, and the y-axis mean is below −.002. **Rejected, no package.**
- The official rerank inference was stopped right after the decision, with 3 partial videos written; those outputs are not used.
- confirm2 cost: 7,078 queries in 4,528 s.
- Reading:
  - The x-axis gain replicates on both splits (+.0174 / +.0179).
  - The y-axis selector is unreliable on both splits.
  - The keyframe oracle is +.09 above DENSE, but the selector only captures about +.01. The bottleneck is the selector, not the candidates.
- A restricted "x-axis only" rerank was not packaged: it was not pre-registered and has not been confirmed independently. It is recorded as a hypothesis for the next round.
