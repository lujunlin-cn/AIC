# AIC 轻量迁移学习与部署方案

研究日期：2026-10-19。固定仓库提交：[`3b28ffc6bf61f0799d91c9ecf6113e83a98223fc`](https://github.com/lujunlin-cn/AIC/commit/3b28ffc6bf61f0799d91c9ecf6113e83a98223fc)。

## 1. 首选架构与实施边界

**首选模块化架构：固定 R54 时间集合及逐视频预算，以可复现的 V9 构图链为基线，接入冻结的轻量前景模型，在原生人工 crop GT 上学习低容量候选窗口读出。** R70 是必须保留的历史强控制；原始 B3 权重未恢复时，不能将 V9 替代链称为原始 B3 的精确复现。[S1][S2]

时间轴先保留 ResNet18 冻结特征加线性读出的语义控制。只有空间 H1 被明确限制、或完成 H1 后仍有资源，才启动 shot 结构与相机补偿残差运动的时间实验。前三项实验均失败时，转向公开、完整上下文、同源联合标注的监督建设。

**H1 空间诊断与约 100M 部署是两条不同的依赖链。** 固定 R54 既有内容选择时，仍继承其 TimeLens 上游，不能靠缓存消去参数。该历史链加现有 V9 空间约为 8.855B，新增模块还需重新核算；具体值以实际实例为准。约 100M 方案以 R91 的 ResNet18 时间链替代 TimeLens，之后必须另验时间及联合效果。仅使用从 N 确定的固定 K 规则不需要 TimeLens。[S4][S8]

本文件是可交给后续实现者的技术设计。**本轮未实现下文的新训练模块、未运行真实视频训练、未改动现役提交包、未上传官方平台。** 已执行的工作仅包括代码读取、确定性合成审计、部分公开权重下载及参数元数据核验。模型实测与未测项目见 `open_models_registry.md`。

### 1.1 哪些能力可以直接复用

| 能力 | 初始状态 | 可复用部分 | 仍需学习或补充的监督 |
|---|---|---|---|
| 显著主体定位 | 可直接复用，需域校准 | U²-Netp 前景 mask；YuNet 人脸；必要时 TinyHD 注意力 | 前景不等于事件主体，需检查非人主体、多人和遮挡 |
| 构图窗口决策 | 需要目标域空间监督 | 原生框适配器、合法窗口生成器、现有 V9 特征 | 主体重要性、留白、尺度和多主体关系；LIVE/RetargetVid 原生 GT |
| 镜头结构识别 | 可直接复用，轻量校准 | PySceneDetect；软转场漏检再比较 TransNetV2 | 小批人工边界检查；阈值只在训练/开发源确定 |
| 运动模式表征 | 可直接提取，需可靠性建模 | DIS；LK/RANSAC 背景运动；残差统计 | 阶段与高光关系需要时间偏好监督，光流本身不提供此标签 |
| 高光偏好排序 | 需要目标域监督 | ResNet18/轻量视频表示；线性或 TCN 适配器 | PHD/GIF 个人选片偏好；新的完整上下文标注 |
| 输出预算与空预测 | 当前不能可靠训练 | 固定预算解码器；精确帧号合同 | 缺少可靠整视频负例和同任务完整标签；先冻结预算，不做空预测校准 |

上述复用表示算子或预训练能力可使用，不表示已在 AIC 上验证。尤其不能将显著性图或运动强度直接命名为 `highlight_probability`。

## 2. 三条迁移路线的比较

### 2.1 路线 A：低维特征与低容量决策头

输入包括位置、shot 长度、切点距离、局部新颖性、显著性分布、主体几何、原始/全局/残差运动和可靠性掩码。初始最多 64 维；在训练源固定每个特征的定义、单位和缺失处理。

时间头先使用 ridge；有明确正例/负例时才使用有概率解释的 logistic。空间头对每个合法候选预测人工平均 IoU。非线性只允许一个预注册的小 MLP 对照，不并行搜索多种树和网络。

优点是来源混杂、归一化错误和每个通路的增量容易审计。主要限制是复杂事件的可分性。R89 的 25 维 ridge 有 26 个学习参数；“零参数”只适用于梯度、帧差等特征算子。[S3]

### 2.2 路线 B：冻结编码器与轻量时序适配器

默认编码器为 headless ResNet18。每秒图像特征与每 0.25 秒运动统计按 PTS 对齐。先做池化静态特征读出，再加入时序残差，不能同时替换 backbone、采样率和解码器。

一个可复核的设计例子如下。它是参数预算示例，不是已经训练好的模型：

| 部件 | 配置 | 参数数 |
|---|---|---:|
| 图像编码器 | ResNet18，移除 1000 类分类层 | 11,176,512 |
| 前景分支 | U²-Netp，保留全部推理层 | 1,131,181 |
| 特征投影 | 512D 图像 + 64D 统计，Linear(576,64)，有 bias | 36,928 |
| 时序卷积 | 3 层 Conv1d(64,64,k=3)，有 bias，dilation=1/2/4 | 37,056 |
| 时间输出 | Linear(64,1)，有 bias | 65 |
| 空间候选头 | 64D 候选描述 → 32 → 1，两个有 bias 的线性层 | 2,113 |
| 合计 | 无额外归一化层、无其他学习分支 | **12,383,855** |

激活、固定池化、DIS、LK、RANSAC 和传统切点检测不增加学习参数，但增加运行成本。若加入人脸、检测器、TransNetV2、DINO 或额外权重，必须重新汇总。以上 headless ResNet18 与 U²-Netp 参数有实现依据；新适配器计数是按给定层结构推导。[S4][M1]

3 层 dilation=1/2/4、kernel=3 的卷积有 15 个采样点的感受野。若统一到 1 FPS 网格，覆盖约 14 秒跨度；它不是逐原帧的瞬时动作编码器。更短的动作由 4 FPS 运动前后窗描述。使用双向窗时说明系统为离线视频处理；不能宣传为零延迟流式模型。

空间主线初期仍以当前强空间链为控制。上述 12.38M 架构是可以比较的替代系统，**不能因更小就直接替换已有高分空间模块**。

### 2.3 路线 C：共享 backbone 的多任务系统

共享 backbone 可减少重复图像计算，分别连接主体、空间候选、时间排序和可观察阶段头。需要两个前提：单任务读出已经可靠；每个训练目标有清晰、可追溯的监督。

没有联合时间—空间 GT 时，采用不同数据源的交替 batch 与任务掩码。空间 batch 只更新空间损失；GIF batch 只更新相应时间目标。不能给 GIF 伪造人工 crop，也不能给 LIVE 框推导高光标签。

| 路线 | 泛化与可调试性 | 数据需求 | 计算特点 | 当前决定 |
|---|---|---|---|---|
| A：低维读出 | 最容易识别单个通路与来源混杂 | 少量源也可作证伪，但 CI 仍按源数决定 | 特征提取占主要成本；训练可在 CPU | 第一轮执行 |
| B：冻结编码器+适配器 | 保留预训练语义，时序能力可控 | 比 A 需要更多源和清晰时间标签 | 编码器可缓存；适配器小 | 时间控制与主要后续方案 |
| C：共享多任务 | 可减少重复计算；任务冲突更难定位 | 高质量多域监督，最好有联合标注 | 可部分微调；工程复杂度最高 | 通过单任务门槛后才研究 |

### 2.4 三档完整系统预算

| 档位 | 代表性完整链 | 判定 |
|---|---|---|
| ≤20M | U²-Netp + ResNet18 + 小适配器 + 传统 motion/shot | 可作为首轮替代系统；完整例子约 12.38M |
| 20M–120M | 当前 V9 空间链 + ResNet18 + 小适配器；或 DINOv2-S 系统 | 本项目重点；需逐项核对冻结模型与缓存依赖 |
| 120M–500M | HL-CLIP 完整双塔或较大教师/视频编码器组合 | 扩展能力控制；不因 head 小而归入 100M |

R91 声明总量 98,584,754。若完整保留其依赖，再加入 U²-Netp 与上表 76,162 参数的新头部，算术上界为 99,792,097。若新头替换旧头，可去除确实未部署的参数，但必须通过依赖审计。这个约 99.79M 例子仍没有证明端到端空间缓存能按该参数链重算。[S4]

## 3. 数据与监督合同

### 3.1 已有数据的真实用途与可用性

本轮读取的是仓库代码、清单、报告及少量公开模型资产。仓库树没有随代码提供完整视频库。以下历史媒体规模不代表当前容器已取得原片。[D1][D2]

| 数据 | 监督与历史规模 | 允许的研究用途 | 需要处理的限制 |
|---|---|---|---|
| PHD / PHD² / PHD-GIFs | 个人 GIF 起止区间与用户；本仓库曾记录 13,993 源、399 GB，clean 5,886 片段/2,262 源 | 个人选片偏好的弱监督、时间表示迁移 | 多个名字不构成独立数据；未选择区间不是可靠非高光；重查原片与时间映射 |
| `gif_soft` | 软时间目标 | 明确生成方式后作弱监督或探索代理 | 不等于官方帧 GT；不继承 `gif_hard` 的缺失语义 |
| `gif_hard` | MrHiSum 的 1,979 行为 `[0]*12` 占位 | 仅做缺失/溯源诊断 | 标记 placeholder，禁止作负例和空视频监督 |
| RetargetVid | 200 视频，6 标注者、2 比例；原生 crop | 空间候选学习与多标注者分析 | 旧池已消费；历史原片链接失效需修复；不可作为新鲜确认 |
| LIVE-YT-VC | 1,800 视频、54,000 稀疏人工框 | 原生空间监督、窗口尺度和主体选择 | 派生轨迹不是新增人工 GT；既有源已暴露 |
| R42 | 540 条记录=360 独立图/12 源，同一账号重复 | 诊断标签政策、上下文需求 | 不能当两名独立标注者；V1.2/V1.3 不混为一致硬 GT |
| TVSum | 50 视频、20 人均值重要性；历史 27/16/7 划分 | 静态表征控制、摘要排序代理 | 已全部参与研究；连续重要性不是二值高光标签 |
| SumMe | 历史两批共 14 条 raw+GT 完成 ordinal 基准并已暴露；当前远端媒体/标签可用性未知 | 资产与许可核验后作摘要迁移对照 | 当前仓库是脚本/配置/报告；14 条不是新鲜确认，不提供空间或 AIC 联合 GT |
| QVHighlights | 文本 query 条件下的时段相关性与显著性 | 条件高光迁移、与语言依赖的竞争解释 | 未评分/不相关片段不等于无条件非高光；跨 clip 去重到原视频 |
| DHF1K | 视频眼动注视分布 | gaze 分支预训练与功能验证 | 与 RetargetVid 等有跨库重复；官方无公开标签的测试部分不用于调参 |
| DAVSOD | 视频显著对象 mask | 动态前景分割及功能验证 | 与 gaze 不是同一标签和 loss；跨库查重，不能当额外独立确认 |
| GAICD / LaSOT 等 | 静态裁切 / 目标跟踪 | 辅助空间能力或跟踪稳定性 | 不能替代事件主体重要性或精确时间监督 |

原始 PHD-GIFs 官方元数据包含 `youtubeId/start/duration/user_id/video_duration/is_last`；标签是用户选择行为，不是对全片逐帧的穷尽判断。[D3]

### 3.2 源级隔离与历史暴露

建立 `source_group_id`，把原视频、切片、旋转版、不同下载版本和跨库重复连成同一组。对明显同一拍摄事件、长视频多片段或重复上传进一步分组。不能只以文件名或 dataset 名称划分。

拆分顺序必须是：先查重及来源连接，再分 train/dev/confirm，最后生成片段与特征。归一化统计、PCA、阈值、补偿可靠性阈值和模型选择都只读训练/开发源。

已有 `rv_confirm2/live_confirm3`、TVSum 旧 holdout 与 LIVE reserve 均按最新暴露台账归为探索。重新随机划分或改名不能使它们成为独立确认。新确认集必须来源未参与本项目模型、规则、阈值或报告选择；预训练重叠另行审计。[D2][D4]

预训练来源无法完全列出时，登记为 `pretrain_overlap=unknown`，同时采用与已知预训练集来源不同的新视频。不能将“未发现重复”写成“证明无预训练重叠”。

### 3.3 标签状态必须显式保存

| 状态 | 训练处理 | 评估处理 |
|---|---|---|
| 人工完整正/负标签 | 按协议监督 | 可计算相应时间 F、PR 或校准 |
| 个人选中区间 | 个人选择目标的正观测 | 计算 observed selection capture |
| 未标注/个人未选 | 不写成硬 0 | 不统计假负例；不能评空预测 |
| placeholder | 强制 mask | 不进入标签分母 |
| 不一致或低置信度 | 软分布/降权或排除 | 分歧单报，保留样本数 |
| 教师 crop/阶段伪标签 | KD 目标，标记 teacher 与版本 | 不能作原生人工 GT 确认 |
| 人工原生 crop | 保留每个标注者与合法性状态 | 平均标注者 IoU，再按源聚合 |

禁止自动用中心框填补教师失败并把该框记成人工标签。对缺失时间点，只在协议允许且邻点均有效时插值。[D5]

## 4. 输入、特征与输出接口

### 4.1 建议数据结构

```python
@dataclass
class FrameRecord:
    source_group_id: str
    video_id: str
    media_sha256: str
    original_frame_id: int       # 0 起始，实际解码顺序
    pts_seconds: float          # 与首帧对齐的实际 PTS
    coded_width: int
    coded_height: int
    rotation_policy: str        # 与既有 coded-pixel 合同一致

@dataclass
class FeatureBank:
    frame_ids: ndarray          # int64 [N]
    pts: ndarray                # float64 [N]
    values: ndarray             # float32 [N,D]
    valid: ndarray              # bool [N,D]，缺失不写成真实零
    shot_id: ndarray            # int32 [N]
    contract_hash: str          # 含特征、预处理、权重、采样配置

@dataclass
class NativeCropLabel:
    video_id: str
    original_frame_id: int
    annotator_id: str
    ratio_wh: tuple[int, int]
    bbox_xywh: tuple[float, float, float, float]
    valid: bool
    coordinate_convention: str
```

数据结构为新接口设计。实现必须额外保存源分组、split、曝光状态、标注版本和模型权重 SHA。

### 4.2 时间合同

所有对照共享同一解码清单、PTS、抽帧表和输出解码器。不能用 `round(t*average_fps)` 处理一般 VFR 视频。现有 `aic.video` 通过解码顺序枚举原帧并检查 PTS；可在回归验证后复用。[S5]

光流端点记录为 `(frame_id_a, frame_id_b, pts_a, pts_b)`。先将低分辨率流按 x/y 缩放分别逆变换回 coded 像素，再以原图对角线和真实 `Δt` 归一化。速度统计的差不直接称主体加速度；后者需要沿可靠轨迹对齐。shot 两侧不求正常运动差分；可靠性缺失单独表示。

将 4 FPS 运动统计池化到时间评分网格时，保留窗起止与覆盖率。最终用固定的 PTS 映射扩展到所有原帧。低频评分的插值不能恢复没观察到的短事件，必须把此限制列入误差审计。

选择器接受外部固定 `K_i`，按分数排序，以预先声明的中心优先、再原帧号规则解决平分。输出准确 K，不因 cell 扩展超额。研究空间 H1 直接复用同一帧列表；研究时间 H2/H3 固定每个原帧的空间结果及其 hash。

### 4.3 空间合同

输出 `bboxes=[x,y,w]`，高度为 `h=w*r_h/r_w`。坐标回到原视频 coded pixels，满足正宽高与完整画内约束。`targetRatioWH` 原样继承 index，不替换成虽等价但不同整数 pair。[S6]

Letterbox/resize 必须记录可逆变换。空间 GT 保持原生坐标约定：half-open 的 `w=r-l` 与 inclusive 的 `w=r-l+1` 不能混算。LIVE 稀疏人工框、平滑框、插值轨迹分开，不能增加派生帧权重来放大样本量。[D1]

候选窗口的尺度不能任意按显著性覆盖扩大。第一轮固定候选族；报告其 GT oracle。若原生框需可变高度而候选仅最大合法窗口，先量化覆盖上限，再决定是否增加尺度。

## 5. 训练目标与迁移顺序

### 5.1 空间候选学习

对一帧和一个目标比例，给候选 `C_j` 的监督为多标注者平均 IoU：

\[
q_j^*=\frac{1}{|A|}\sum_{a\in A}\operatorname{IoU}(C_j,G_a).
\]

使用 masked SmoothL1 回归 `q_j*`，可辅以同帧候选排序损失。学习目标是合法窗口的人工重叠，不能只用 foreground coverage。源级采样避免标注帧多的视频支配损失。保留每个 annotator 的分歧，不先平均 box 坐标制造一个未被任何人选择的“真值框”。

主体分支默认冻结。若新头只学到全局向中心偏移，在匹配中心偏置的控制组上没有收益，则拒绝“主体理解改善”的解释。

### 5.2 时间偏好学习

对有完整二值标签的数据，可采用按源等权的 masked BCE 或 pairwise ranking，并以固定 K 集合指标选择模型。连续 TVSum 重要性采用回归/排序，不能直接传入标准二值 AP 的实现。[S7]

PHD/GIF 采用个人选择的条件目标。例如令 `r_t` 为该用户观测 GIF 区间内归一化的选择质量，最小化：

\[
L_{choice}=-\sum_t r_t\log\frac{\exp(s_t/\tau)}{\sum_{u\in video}\exp(s_u/\tau)}.
\]

该目标描述“已观察到一次选择时，选择分配在哪里”。第一轮 `s_t` 不含用户 ID 或历史嵌入，学到的是按用户/视频平衡的人群观察选择分布，不是个性化预测。它让所有候选竞争选择概率，**含有弱偏好假设，但没有把未选择帧标成普遍非高光**。需要控制 GIF 长度与用户偏好偏差；不能解释为完整标签 BCE，也不能据此校准空视频概率。温度只在开发源固定，不通过官方反馈调节。

若需要 PU 风险估计，必须另有可靠 class prior 或可识别性假设；不能从占位零或未选比例估计它。第一轮不引入这项额外不确定性。

### 5.3 冻结层、部分微调与蒸馏

依次执行以下顺序，不跳级：

1. 一个冻结 backbone、同一解码器、单一线性读出。检查目标定义与输入对齐。
2. 保持 backbone 不变，加入通过 H2/H3 的特征和小 TCN。与等参数静态 MLP 比较时序增量。
3. 只有冻结表示有源外信号、错误显示表征分离不足、监督质量合格，才解冻最后一个视觉 stage 或使用少量适配层。
4. 同等数据和预算下，部分微调超过冻结头，才考虑更广解冻。
5. 蒸馏只在公开训练源上运行教师，保存 teacher SHA、输入与伪标签置信度。低置信度或跨主体错误不传递为硬 GT。

冻结信号不足并不在逻辑上证明微调永远无效；它只是当前资源与证据下的停止门槛。重新启动必须有新监督、新的输入或明确的可诊断误差机制。

### 5.4 多任务损失

\[
L=\lambda_t m_tL_{choice/temporal}
+\lambda_s m_sL_{crop}
+\lambda_m m_mL_{motion}
+\lambda_c m_cL_{consistency}.
\]

`m` 是真实监督可用性掩码。`L_motion` 若为光流蒸馏，表示逼近教师流，不是学习人工动作阶段；阶段标签只能来自实际标注。`L_consistency` 只在同主体、同 shot、可靠运动对应上启用，跨切点及遮挡时关闭。

先逐任务记录梯度方向与性能。若共享更新损害独立任务，冻结共享层或分开适配器。是否共享由同预算下的源外结果决定，不由参数更少单独决定。没有联合 GT 时，不声称优化了官方完整联合 F。

下表的规模是建议上限或计划样例，均非本轮已执行训练。

| 阶段 | 输入 → 输出 | 模型/数据量 | 资源与存储假设 | 风险 | 通过或终止条件 |
|---|---|---|---|---|---|
| Phase 0 合同与谱系 | 固定代码、规则、清单 → 审计报告、权重依赖表、split/时间轴 hash | 既有所有清单；少量可解码原片与合成边界 | CPU；文本与元数据通常远小于媒体；实际大小按清单记 | 旧评分系数、原始 B3 不可恢复、缓存模型不明 | 评分、标签、原帧与可复现强基线全部闭环；否则不进入新实验 |
| Phase 1 特征诊断 | 已暴露开发源 → 低维 bank、分布、可靠性、候选 oracle | 先 40 个不同源作抽样诊断，再按预注册数据规模扩展 | CPU motion/shot；可选单 CUDA GPU 冻结前景；例子见 6.1 | 中心/位置/来源混杂，运动补偿失败 | 修正特征依赖；确认 oracle 与可测信号；没有空间则停止对应头训练 |
| Phase 2 最小读出 | 固定 bank+真实标签 → 一个 H1 模型及冻结比较清单 | 既有开发源训练；新确认源 N 由功效决定 | CPU ridge/小 MLP；不新提重模型特征 | 小源数、历史确认池复用 | 按 H1 的 source CI/最小增益/类别门槛决策 |
| Phase 3 冻结时序适配 | ResNet18 特征+H2/H3信号 → 冻结 encoder 的时间头 | source-disjoint PHD/GIF；目标规模依媒体审核，先限定单一适配器 | CPU 或单 GPU；缓存一次；不并行多个 backbone | 弱选择标签与比赛偏好不同 | 只在独立时间代理验证通过后继续；仍不合成官方分数 |

### 6.1 可复算的资源估计例子

假设 200 个视频，每个 120 秒，总时长 24,000 秒。语义采样 1 FPS，运动 4 FPS；忽略每个视频末端少量不足窗，约 24,000 个语义帧、96,000 个运动采样点。

| 产物 | 算式 | 十进制存储估计 |
|---|---|---:|
| 原视频 | 总时长 × 1–4 Mb/s ÷8 | 3–12 GB，码率是假设 |
| 64D float32，4 FPS | 96,000×64×4 | 24.576 MB |
| 512D float16，1 FPS | 24,000×512×2 | 24.576 MB |
| 320×180 双通道 float32 稠密流 | 96,000×320×180×2×4 | 44.237 GB |
| 224×224 RGB uint8 全量帧 | 96,000×224×224×3 | 14.451 GB |

因此默认保存低维统计、抽样流可视化、时间轴与 hash，不保存全部稠密流或解码帧。NPZ/Parquet 的压缩效果依数据而变，不在计划里保证压缩比。

先用固定的 1,000 帧记录解码、预处理、模型、后处理各自耗时、峰值内存、加速器显存。全量时间按 `T≈N/v + decode + I/O` 外推，并报告长视频与短视频差异。若端到端实测吞吐恰为 10 帧/秒，96,000 帧约需 2.67 小时；这是条件算例，不是对某模型的速度承诺。

## 7. CPU、CUDA 与 Ascend 910A

### 7.1 本轮实际设备状态

当前执行容器为 x86_64，Python 3.12.14，逻辑 CPU 数为 9；可找到 ffmpeg，未找到 `nvidia-smi` 或 `npu-smi`。本轮未连接历史 GPU/NPU 主机，未验证其在线情况。该检查不能证明所有远端设备不存在。具体记录随证据包提供。

### 7.2 部署分工与迁移风险

| 环境 | 首选执行内容 | 必须验证的条件 |
|---|---|---|
| CPU | 解码、传统 shot、LK/RANSAC、DIS、低维统计、ridge | OpenCV/FFmpeg 版本、线程数、解码一致性；CPU 算法也要计运行时间 |
| 单 CUDA GPU | 冻结 U²-Netp/ResNet18、必要时 TCN 或局部微调 | 权重加载 key、batch/分辨率、FP32/FP16 差异、峰值内存与吞吐 |
| 现有 NVIDIA 环境 | 在原环境先复现输出，再做版本迁移 | 不因旧代码可 import 就认为全部权重/处理器一致；V100/RTX 分别记录条件 |
| Ascend 910A | CPU 保留传统运动；优先迁移标准卷积/线性/插值的小网络 | 确认具体硬件、驱动、CANN、TorchNPU/PyTorch 兼容组合；实际 operator smoke test |

910A 上重点检查：动态 shape、`grid_sample`/相关体、`unfold`、插值坐标规则、排序平分、逐步扫描和 dtype 支持。不能把最新文档中面向其他 Ascend 型号的支持表直接套到 910A。官方安装页要求按 CANN 与 PyTorch 配置匹配 TorchNPU，故不在未查看机器版本时指定“一键升级到最新版”。[H1][H2]

建立少量公开片段的 FP32 CPU/CUDA 参考输出。迁移后比较特征误差、最终所选帧集合和框坐标；仅 feature 均方误差小不保证排名不变。FP16/BF16 是否适用需由具体设备和算子验证，不能预设。

RAFT 类相关体与迭代更新若在 NPU 上造成显著工程成本，优先保留 CPU DIS；只有 H3 显示传统流的具体错误限制收益时，才支付深度流迁移成本。

## 8. 参数、权重与缓存的完整审计

### 8.1 计数原则

完整推理参数为所有必需模型的唯一参数张量总元素数。冻结 backbone、空间检测器、文本塔、用于测试视频预提取的模型都计入。LoRA 只训练少量参数不等于只部署少量参数；教师若用于测试输入特征或伪标签，也属于推理链依赖。[O1]

仅用于公开训练数据蒸馏、部署时不再使用的教师单独记录为训练依赖。若官方后续规则对训练教师另有要求，按对应规则核对。所有 buffer、归一化统计、权重字节、激活内存另外记录，不能以它们替代参数数。

```python
def audit_runtime_dependencies(model_graph, weight_manifest):
    # 设计要求：逐个已加载模块统计、检查共享/绑权与张量身份
    # 输出 total_parameters / trainable_parameters / buffers / weight_bytes
    # 输出每个测试特征缓存的上游模型、权重SHA和预处理版本
    # 未知上游依赖 => incomplete，不给“完整100M已验证”的结论
    ...
```

同一共享 backbone 物理复用一次；两个分别存储并调用的副本按实际部署记录，不能因名称相同任意去重。量化能减少字节和计算，不改变原网络参数元素的定义。

## 9. 最终集成验收

按以下顺序验收，不用官方提交代替本地调试：

1. 现行评分公式与 schema 修复完成，纯合成样例覆盖双空、单空、完美框、一帧偏移、越界、重复、缺字段、NaN、参数上限及非法值。保留 `official_evaluator_verified=false`，直到取得并核验同版本官方可执行 evaluator。
2. 原视频、时间轴、目标比例、split、特征、模型权重与读出都有版本和 SHA。缓存被删除后能在公开原片上重算。
3. H1 固定时间 hash；H2/H3 固定逐帧空间 hash 与预算；评估脚本只读公开标签，打包脚本没有 GT 输入。
4. 空间、时间代理分别达门槛。若无联合 GT，报告不合成伪官方分数；可先作机械集成回归，不能据此宣称联合收益。
5. 使用同一配置重复推理，验证精确帧 ID、数量、合法坐标和依赖总参数。数值非确定性会改变排名时，应固定可复现的 tie/quantization 策略并重新验证。
6. 形成可审查候选 ZIP、变更摘要和固定证据。是否进行之后的单次官方验证属于后续明确决策，本轮不执行。
