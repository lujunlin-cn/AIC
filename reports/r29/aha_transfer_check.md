# R29 AHA transfer mechanism check

Date: 2026-10-16. CPU/read-only primary-source review; no training, GPU job, parameter recount, official-test labels, or prompt search. Paper: [arXiv 2509.16421v2](https://arxiv.org/html/2509.16421v2). Author code: [aiden200/Aha-](https://github.com/aiden200/Aha-), remote checkout `41473169504ae3793811066ffd398bc69094e499`. Hashes, verbatim short extracts and locators are in `aha_transfer_evidence.json`.

## Judgment that changes the next experiment

Do not give another direct generic-query AHA replacement priority. Its three heads do not jointly estimate the competition utility. Relevance is trained against normalized replay engagement; informativeness against a segment-phase heuristic; uncertainty against error in that relevance prediction. None is supervised by native crop IoU. The R29 source-level controls independently reviewed here did not establish additional useful signal from the existing two scalar heads beyond position. This supports stopping this *configuration*, not declaring that AHA contains no content information.

The strongest alternative explanation is deployment/task mismatch: our all-purpose query and full growing past cache differ from the paper's task-conditioned, bounded-memory setting. Primary-source inspection makes that explanation concrete, but provides no evidence that correcting it improves this competition. AHA's original transfer results also use different labels and ranking metrics. The next expenditure should acquire identifiable supervision/content evidence, rather than use official submissions to search fusion weights or prompts.

## What the heads actually learn

**Literature claim, not a project measurement.** Sections 1 and 3 define strictly causal, task-conditioned online highlight detection. The fixed natural-language objective is known at the beginning; future frames and bidirectional full-video context are unavailable. Our task permits offline use of the entire video and does not supply a query. Thus AHA's causal constraint deliberately forgoes potentially valuable future evidence; adding a generic query does not establish query-free transfer.

Section 3.3 says HIHD originates from original YouTube videos referenced by Mr.HiSum; videos below 70,000 views are discarded. Its 1fps relevance target is replay counts normalized to [0,1]. Query text comes from the original YouTube title through templates. HIHD follows Mr.HiSum splits. Consequently its relevance head may learn engagement, title-relatedness, source selection and editing policies. These can coincide with competition highlights, but their equality is an unverified transport assumption. Known Mr.HiSum benchmark scores cannot serve as fresh-source evidence for this model.

The informativeness labels are more specific than the name implies. Section 3.3 and Appendix D.1 take captioned Shot2Story/COIN segments, choose an understanding point U between 50% and 75% of each segment, label frames from the 50% point to U positive, and all other segment frames negative. These are not human per-frame ratings of novelty or highlight value. The underlying implementation reviewed here encodes informative labels from stream/assistant turn placement (`data/stream.py:169–185`); HIHD explicitly returns no informative labels (`data/HIHD.py:92–94`). We did not reconstruct the serialized historical Shot2Story/COIN preprocessing; bounded search found no direct numeric 0.75 rule in the reviewed Python/shell preprocessing files. Therefore the exact heuristic is a paper-confirmed training description, not independently re-generated checkpoint training provenance.

**Mathematical consequence under stated assumptions.** If segment-relative time is s and labels follow the paper's construction, then `P(i=1 | s) = 1{s>=0.5} P(U>=s)`. If U is uniform on [0.5,0.75], this is 0 outside that interval and `3-4s` inside it. The paper does not explicitly specify the sampling distribution; uniformity is an additional assumption. A phase predictor can therefore reduce the training loss without learning an independent value judgment. This is a *local segment-phase* prior, not proof of a global video-center prior. Nor does it prove our observed score trend is caused by this heuristic: visual/contextual novelty, RoPE/cache length, query and source policy remain competing explanations.

Appendix C.1 motivates relevance TV regularization by bell-shaped replay engagement curves. This shapes smoothness around replay peaks; it is not a proof that a constant-input model must learn a video-centered bell curve. Relevant content can still exist in either head.

The uncertainty head is Gaussian relevance log variance, trained with NLL and a variance-diversity term. It is not a calibrated probability that a selected frame is a true highlight, and is not crop reliability. Reliability-based competition decisions require separate calibration against the actual target.

## Actual deployment comparison

R25 and R26 use the identical literal query `Identify the most informative and important highlights of this video.` and the same system instruction. They use real frame embeddings and causal `past_key_values`, not text-only inference. The heads are read from each frame's final visual token; the scripts check 49 visual tokens/frame, finite outputs, exact source-head weight identity and first-chunk native-forward difference below 1e-5. Those implementation checks support the real visual path. They do not validate the generic query's semantics.

Both scripts rank `softmax(informative)[1] + sigmoid(relevance)`. They save raw uncertainty log variance but do not use it. Both initialize `past=None`, pass the returned cache onward, and install no explicit SinkCache/SlidingWindowCache. Their full history differs from the paper's recommended 2048-token visual window plus task sink. No claim is made here about the underlying default transformer's implicit window settings, because its exact loaded config/cache class was not live-instantiated in this CPU review.

The author's code has relevant differences even from the paper description:

- `models/live_llava/video_head_live_llava_qwen.py:185–188,327` outputs informative logits, sigmoid relevance and raw log variance. This agrees with the R25/R26 native-head transformation; a second sigmoid must not be applied to its already-sigmoid relevance output.
- `test/inference.py:227` applies `exp` to returned raw log variance. `test/grid_search.py:60–64,99–103` then thresholds this quantity and subtracts epsilon times excess. The paper's fusion text instead identifies uncertainty as *clamped log variance*. Its training code clamps log variance inside the loss, while returning raw log variance. These scales are different.
- Author `test/inference.py:133–155` constructs bounded sink/sliding/static alternatives, but the task-query sink reinitialization shown at lines 249–253 is commented out in this checkout. Do not describe that version as verified active task-only DynamicSinkCache.
- Main-text zero-shot ratio 10:7 disagrees with Appendix C.4's alpha=.7, beta=1.0. Appendix C.4 also prints epsilon=-2.9; in the displayed subtract-penalty rule a negative epsilon *rewards* excess uncertainty. The author grid permits epsilon from -5 to 5. These facts prevent treating its formula as a universally risk-averse, calibrated decision rule. Appendix Table 12 even sets informativeness weight to zero for Mr.HiSum.

These are reasons to freeze a precise executable contract before a new AHA trial. They are not evidence that the historical official score would improve after adopting one of those variants. Existing R26 exact-budget controls already address the earlier whole-cell keep overshoot; this review does not reopen that audit.

## What would overturn the current decision

A minimal future AHA pilot needs a task description available independently of GT, explicit query and cache variants, identical actual input frames/processor, and a frozen uncertainty representation. Use legal TRAIN to select one bounded variant and calibrate it; reserve source-separated DEV for the one comparison. Include position-only, position-plus-heads and same-per-source-K controls, and all-select as a reference. A gain only over AHA's current equal fusion is insufficient if the position baseline explains it. Compare raw heads before selecting prompts from DEV outcomes. Use source-level paired uncertainty, report per-rater temporal utility, and label this as temporal development evidence; native crop GT and independent sources remain separate deployment gates.

The falsifying result is reproducible, practically useful content increment beyond position and matched output counts on held-out sources, followed by confirmation on new sources. If a task-aware/bounded-memory variant changes output but does not establish that increment, stop that AHA recipe. If a head/readout pilot succeeds, AHA could supply source-traceable TRAIN-only features or labels, but student supervision must still be validated; teacher confidence, eloquent text or teacher agreement is not ground truth. Official test is excluded from training, pseudo-labels, manual annotation and prompt selection.

The existing R29 temporal test used 26 TRAIN and 14 previously exposed DEV sources and two scalar AHA heads. It is not the above independent confirmation. Its negative fixed-budget increment cannot reject alternative queries, full hidden representations, bidirectional context, or new valid supervision. This narrower conclusion is sufficient to de-prioritize an otherwise unbounded AHA search now.
