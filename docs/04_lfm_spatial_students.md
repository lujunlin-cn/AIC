# 路线 04：LFM 小模型空间候选效用学习与蒸馏

整理日期：2026-11-07。总入口：[index.md](index.md)。当前规则只按全部推理参数≤9B判断资格，历史“≤500M档奖励”不再成立。

## 主假设与实际结构

将构图从自由生成坐标改为有限合法窗口选择：`LFM2.5-VL-450M视觉塔 → 129个最大合法窗口 → win/out token池化及位置 → 候选效用头 → argmax窗口`。

V7头输入2305维、约1.511M参数；使用RetargetVid多标注员平均crop IoU监督、Huber+pairwise。完整早期学生约450.283M参数。后续vision-only V9部署约87.408M参数，是不同实际组件清单，不能混计。

## 纠错与仍有效的认识

V8曾把旋转数据错误接到原生split，B1/B2结果位级相同；修复按 `(split,src)` 区分后重跑，错误臂作废。几何增强必须核对自由轴和目标比例，旋转源图不必然生成所需“竖源→16:9上下滑”任务。

教师blend错帧已纠正；NPU升级曾导致SigLIP2位置嵌入全零，后续加入CPU插值与CPU/NPU parity。错误栈缓存的读数不能与健康栈比较。

`B3`可能指训练数据配方、完整LFM系统、某个具体候选头或V9导出空间父集。报告应记录实际checkpoint与推理组件，名字相同不代表权重和输入相同。

## 与 GPT 讨论的问题

1. 候选oracle仍高于模型时，怎样区分“候选内读出不足”和“人工偏好不可预测”，避免把oracle差全部承诺为可学收益？
2. 增量应来自原生几何监督、更高分辨率局部观察还是候选偏好训练？哪些已有匹配负控制？
3. 是否值得保留小空间组件，与一个强时间模型组合？总参数和实际runtime应如何核验？
