## 0. 一句话结论

> **我们缺的不是一个更强的排序器，而是一把还没造好的尺子。**
> 项目 steering 用的每一个本地数字——0.3340、0.7404、−0.0994、0.7085、0.5671——
> 现在都被判定为**泄漏读数、行号错配、或指标混比**。
> 因此下一步不是第 13 轮排序头，而是**先重建测量仪器，再做一次可判定的实验**。
> 官方轴（分数口径、天花板代数）不受影响：现役 35.52，p=0.8534 处天花板 39.5。

### 1.3 新增阻断项（做任何实验前必须闭掉）

1. **标签语义未知** —— 2508 行中 **1979 个 MrHiSum 片段的 `gif_hard` 是 12 个零**
   （全池全零 1983/2508 = **79.07%**，不是此前说的 87%）。原始构造器未恢复，
   **既不能当已验证真负，也不能无条件删**。
2. **源身份未绑定** —— `mrhs_video_N_offset` 需映回 YouTube 原源；2508 行实为 **1329 个规范源**。
   legacy hold125 有 **98/123** 行与 train 同源。
3. **缓存合同破裂** —— 禁止跨池复用行号；每行必须绑定
   `(source_id, media_hash, actual_pts, preprocess)`。
4. **头身份不一致** —— VPB checkpoint 含 `norm=(mu,sd)`、原训练用 GELU/标准化，
   被审计的副本改成 **ReLU 且漏掉标准化**。同 shape 能加载 ≠ 同一预测器。
5. **确认池已耗尽** —— LIVE 1800 源均有历史 exposure；227 "reserve" 与旧 R11 confirmation
   完全相同。历史门未闭环的 protected 只能降为开发。

## 2. 我独立复核的一条修正（对 R21 的补充）

R21 的泄漏结论针对**旧池**（centered125 / uniform125 / U8 的 324 段 holdout）成立，
但**不适用于 R16_EXEC 的 T1\* / T1S\* 臂**。我核对了
`/root/autodl-tmp/experiments/R16_EXEC/public_uniform_group_v1.json`：

```
train 121 源 / dev 40 源 / eval 42 源，并集 203
dev∩train = 0    eval∩train = 0    eval∩dev = 0      （裸 11 字符 YouTube ID 直接比对）
T1S_uniform_s13_v1 的 42 个 eval 源 ∩ train = 0
```

⇒ R16 的 8 条 T1/T1S 臂用的是**源级互斥划分**，其读数不因 R21 的行号错配而作废。

**但 R16 的 E1.1 判决仍然成立，只是理由要换**：

| 臂 | keep=0.85 F | 对照 |
|---|---|---|
| T1_uniform_s13 | 0.2549 | position_only 0.2404 / random 0.2422 / select_all 0.2470 |
| T1S_uniform_s17 | 0.2538 | 同上 |
| T1_uniform_s17 | 0.2482 | 同上 |
| T1_centered_s17 | 0.2487 | position_only 0.2511 / random 0.2422 / select_all 0.2470 |
| T1S_uniform_s13 | 0.2352 | 同上 |

均匀池上位置先验确实塌了（0.2511→0.2404），但模型也没站住：
**8 条臂全部落在三控制带 [0.2404, 0.2470] 的上下 ±0.008 内**，
没有任何一条对预定控制形成稳定优势。

**关键修正**：`scripts/r15b_content_signal_verdict.py` 自己的判决文本写的是
「若模型下降，仅说明本协议可学信号减弱；**源级独立评估前不得判内容不存在或 35.52 终局**」。
反而是 `r15b_experiment_plan_table.md` §1 把判据写成了「模型也塌 → 内容不存在，35.52 终局」——
**计划表比脚本更激进，且这个激进版本与 R21 的结论冲突**。
本文采用脚本版本：**E1.1 的结论是"本协议下可学信号弱"，不是"任务无内容信号"。**

### 待核实（R16 侧，1 项）

`T1S_uniform_s13_v1/config.json` 声明 `manifest_sha256 = a5de5742f51a…`，
而该路径下 `public_uniform_group_v1.json` 实测 sha256 = `016a3f0340866…`。
**两者不一致**——要么划分文件在 run 之后被重新生成，要么 run 用的是别处的 manifest。
在把它当"已认证源级划分"之前必须闭掉（同一 `manifest_sha256` 是否指向其它路径的副本）。

## 3. 这些数字现在怎么读

| 事实 | 旧解释 | 现在的解释 |
|---|---|---|
| 三种外部监督纹丝不动（PHD2/QV/MrHiSum 全锁 34.9–35.2） | "瓶颈不是监督信号" | 仍然对；且 p=0.8534 天花板 39.5，已在 89.8% —— **但这是相对于一个未被认证的 ρ 反解** |
| 换 backbone / 加头 / 换损失都无迁移 | "模型容量不是瓶颈" | 仍对；但**我们也从没在有效标签上测过**——旧读数全有泄漏或错配 |
| lift ≈ 1.05 | "排序器接近随机" | 数学成立，**但 ρ 是从 6 个官方分反解的**；且在 (d, R̄) 不可识别下有依赖 |
| 0.3340 vs 0.5671 | "41% 信号来自位置先验" | **作废**：两者都是有泄漏的开发读数，差值不可解释 |
| 45 分对手 | "核心不在视频理解" | 代数上可解释：`200·R̄·d/(p+d)` 在 p=0.5、R̄=0.784、d=0.2847 时 ≈ 56.9 —— **低 keep + 高 ρ 就能到 45，不需要更强视觉** |

**战略含义**：官方分对 `(ρ, p, R̄, d)` 的敏感度远大于对"视觉理解能力"的敏感度。
在 p=0.8534 上怎么堆模型都到不了 40（算术上界 39.5）；要越过 39.5 必须
**同时**把 keep 压到 ~0.55 以下 **且** 把 lift 提到 ≥1.17。这是一次带门槛的跳跃，
而不是调参。而这跳跃的**前提是内容信号真实存在**——这一点现在既没被证明也没有被证伪。

## 4. 后续研究方向

四条线，按"能否改变决策"排序。

### 主线 1（P0）：重建测量仪器 —— 不产分，但没它后面全是噪音

把五个阻断项逐一闭掉，产出一个**可复现、源级绑定、标签语义明确**的评估集。
验收：任意两次评估之间，`(source_id, media_hash, actual_pts, preprocess)` 四元组
能逐行对上；全零标签有明确的 `label_status ∈ {verified_negative, unknown, placeholder}`。

### 主线 2（P0）：随机排序探针 —— 全场最高信息量的一次提交

`docs/r15d_ceiling_and_identifiability.md` §4。空间 bbox 逐字节复制现役 B3（R̄ 恒定），
时间换成**与内容无关的逐视频固定伪随机 Bernoulli(p)**，此时 `ρ ≡ p` **精确成立**
（不是近似），得 `S_rand(p) = F_ANCHOR·(1+d)·p/(p+d)` —— **只剩 d 一个未知量**。

- 交 p=0.5 与 p=0.8 两点：p=0.5 单点即可分辨 d∈[0.21,1.0]，极差 **6.4 分**
  （大于全部 6 次实测总跨度 2.95 分）。
- **它不依赖任何本地标签有效性**——这正是它现在价值最高的原因：其他所有实验都被 §1.3 卡住，
  只有它不受影响。
- 约束：消耗官方提交次数，需先确认剩余额度；伪随机必须逐视频固定种子、非均匀间隔；
  提交前过本地 validator。

### 主线 3（P1）：在有效监督上做一次判决性 point-vs-block

R19 已用完整 10 人 GT 发现**块目标有容量差异**（keep=0.85 下 block12−point12 **+0.006746**
CI[0.002214, 0.011612]；keep=0.15 下 block48 比 block12 **+0.100858** CI[0.081642, 0.121294]，
而 rater 间不一致下限 **0.337965**）。但那是 **GT 辅助的 oracle 排序，不是可学增益**。
⇒ 在主线 1 产出的新源上，用冻结 VPB 12 帧同时序输入跑 point/block 两臂 × seed 13/17，
同头/同初始化/同归一化。**开发门：配对 F@0.85 均值差 ≥ 0.005 且两 seed 非负且稳胜控制。**

### 主线 4（P2）：AHA 有界真实视觉 smoke

资产已在位（`aha_repo` / `aha_env` / LLaVA-OV 基座 4 shards / `aha_weights`），
**从未加载**。只做一个：单卡 32GB、公共 TRAIN 视频、batch=1、真实视觉输入、单进程 ≤20min
（含加载），记录 relevance/informativeness/uncertainty 三头输出、实测显存/时延、
以及**输入真实变化时输出的响应差异**。图像无关的纯文本 smoke 不算通过。
**参数合同**：序列化相加 8,632,711,712 elements **不是**实际推理参数（adapter 含完整
`lm_head`/`mm_projector` 替换模块，未 merge 账面 8,070,733,344 / merge 后 8,030,363,168，
且需加空间与辅助分支）。在任何 ≤9B 声明前必须落实实际 loader/merge/tie 行为。

## 5. 执行计划

### 阶段 0：先确认，别先动手（0 GPU，~1h）

| # | 动作 | 产出 / 判据 | 阻塞谁 |
|---|---|---|---|
| 0.1 | 核实官方提交次数余额 | 决定主线 2 能否执行 | 主线 2 |
| 0.2 | 闭掉 §2 的 `manifest_sha256` 不一致 | 要么找到 `a5de5742…` 的实际文件并确认 = R16 划分，要么记为未认证 | 主线 3 |
| 0.3 | 追 MrHiSum `gif_hard` 原始构造链 | 恢复构造器；否则把 1979 行全量标 `label_status=unknown` | 主线 1、3 |
| 0.4 | 核实 35.52 的上传 SHA 与平台记录对应 | 现役 manifest 的官方分仍是 `null`、模型说明仍写 zero-shot、漏列 VPB/LoRA/评分头 | 全部（材料合规） |

**0.4 是材料合规风险，不只是记账**：现役最佳包的自述与实际组成不符，
在需要提交材料复核时是硬伤。

### 阶段 1：重建仪器（CPU + 有界下载，~1 天）

1. **新 64 源**（R20 已冻结清单，`candidate_sources.jsonl`，约 1.395 GB）：
   2 GB / 40 min 预算内做有界恢复 + 完整解码 + raw-second 区间 QC + 采样唯一性。
   32 train / 16 dev / 16 protected。**protected 是预留，不是 fresh 认证**——
   历史门未闭环前只能降为开发。
2. **规范源映射**：`mrhs_video_N_offset` → YouTube 原源；PHD2 保留完整 11 字符 ID。
   按**规范源**划分，不按行号。
3. **缓存重绑**：每行绑 `(source_id, media_hash, actual_pts, preprocess, feature_revision)`。
   **禁止跨池复用行号**——这是 0.3340 与 −0.0994 两次翻车的直接原因。
4. **头身份恢复**：VPB 评分头恢复 checkpoint 的 `norm=(mu,sd)` 与 GELU。
   在做任何历史预测器对比前，先证明恢复后能重现旧读数。

验收：`label_status` 分布明确；源级划分可验证互斥；同一入口两次运行读数一致。

### 阶段 2：判决实验（单卡 RTX 4080，每臂 <10min，超时 45min）

- 冻结 VPB 12 帧全轴输入，point-vs-block 两臂 × seed 13/17。
- **开发门（沿用 R20，不放松）**：配对 F@0.85 均值差 ≥ 0.005，两 seed 非负，
  且稳定胜 `position_only` / `fixed32 random` / `select_all` / 同分固定块 四个预定控制。
- **过门**：仅在独立历史门已满足时，做**一次** protected 评估。
  **不过门**：停止该配方，**不换 seed、不换阈值、不换源再来一遍**。

报告口径：逐 rater 时间 F → 源级 macro；同时报 precision/recall、**实际保留帧数**、
边界、域、no-highlight 行为。**不得用 shot Pearson 替代**；**不得声称空间 IoU 或官方分**。

### 阶段 3：表示比较（仅在阶段 1 之后）

同头 / 同初始化 / 同归一化 / 同损失 / 同训练采样 / 同选模规则，
比较现有冻结 **VideoPrism-B vs CLIP ViT-B/16**，显式记录输入适配器 512 vs 768 的参数差。
**不从旧 0.7404 出发去扫 SigLIP-L / DINO-L / InternVideo2**——那是从污染读数出发。

### 阶段 4：AHA 有界 smoke（并行，不阻塞主线）

见 §4 主线 4。失败即保存首次失败与最小原因，**不重装环境、不重复下载、不申请 PRO6000**。

### 阶段 5：空间线（独立，被阻塞）

LFM vs DINO 仍需**新 native x/y 人工 crop GT**（≥24 portrait + ≥24 landscape，
每源 6 帧，2 名独立标注者）。公开 crop regret **不得**换算官方涨分：
固定时间集合与匹配关系下 `ΔScore = 100·mean_video(F_temporal · mean_matched(ΔIoU))`，
其余情况无换算依据。

## 6. 资源与硬约束

- 单卡 **RTX 4080 32GB**（AutoDL `40206`，GPU0）。每个小头超时 45 min、预期 <10 min。
- **单次训练严格 <12h**；阶段 1–3 全部为 CPU 或有界小任务，不触发大训练。
- 未来解冻/SFT/千视频级/>1h 正式训练/PRO6000：**事前**在文档与对话中说明用途、
  数据与对照、实测资源、时长与存储预算、启动与中止条件。
- 不处理未识别进程；占用即换或等待。

---

## 7. 停止规则

1. 身份/QC/泄漏错误、非有限值、OOM、GPU 被占、预算风险、开发门不过 → **停该臂**，
   保存失败，不做 seed/阈值循环。
2. **禁止在拟合区间外使用拟合函数形式外推**（KF050 在 p=0.545 预测 36.37、实测 32.57，
   −3.80 的教训）。
3. **禁止 `score/k_size` 换算**（10-02、10-04 已两次犯，10-15 又差点第三次）。
4. 某个方向连续多个公平实验都不能提高 **official-like metric** 且无新机制假设 → 降优先级。
5. 不要因为"再调一点超参可能就好"而无限循环。

## 8. 一句话交回

**先造尺子，再量东西。** 阶段 0.1–0.4 是一小时的文书与核实工作，
却决定后面所有实验是否可解释；阶段 1 是唯一能把"内容信号到底存不存在"
从争论变成测量的路径。在它完成之前，任何新排序头、新 backbone、新损失的收益
都无法与泄漏、错配、混比区分开——这正是过去 12 轮的真实处境。
